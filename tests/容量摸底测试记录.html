六、依赖组件检查

  • MySQL 慢查询数为 0，测试结束时运行线程数为 2。
  • RabbitMQ 各业务队列的 ready 和 unacked 消息数均为 0。
  • Elasticsearch 集群状态为 green，没有未分配分片。
  • 测试容器没有发生 OOM。

七、结论和限制

  • 4 倍数据规模下，Elasticsearch CPU 是当前首个资源瓶颈。
  • 标准容量测试的保守基线为单实例 128 并发、约 1,000 req/s。
  • 资源上限测试的 1,700 req/s 包含约 9.5% 的 503，不应作为可用容量。
  • 测试关闭了业务限流，并提高了 API 资源保护阈值，结果不能直接替代生产配置下的容量结论。
  • 测试未包含前端、网关、真实用户流量分布、写入链路和持续稳定性测试。
  • 测试使用临时 Compose 项目；测试容器已停止，4 倍测试数据卷已保留。
