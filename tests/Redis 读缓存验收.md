# Redis 读缓存验收

## 试验条件

2026-11-21（UTC），在本机单独的 Compose 项目 `gopulse-redis-read-cache` 中执行压测。负载发生器直连 API 的本地端口。隔离项目与本机已有服务共享宿主机。预检基线使用 `af5d4272`，逐期开关对照统一使用 `19feabdc`。基线和候选版都仅在测试副本上增加了本地 MySQL 连接池采样端口。

每轮为 API、MySQL、Redis、RabbitMQ、Elasticsearch、Worker 和 Indexer 各运行 1 个容器。容器配额取自根 `compose.yml`。API 为 2 vCPU 和 1 GiB，MySQL 为 3 vCPU 和 2.5 GiB，Redis 为 1 vCPU 和 2 GiB，Elasticsearch 为 3 vCPU 和 4.5 GiB。应用连接池上限为 8，Redis 内存上限为 1,800 MiB，淘汰策略为 `allkeys-lru`。容量测试期间启用共享限流。

数据集包含 1,000 个用户、5,000 篇帖子、200,000 条评论、320,000 条点赞和 5,000 个搜索文档。每档测试前清理测试写入并清空隔离 Redis，再按相同规则预热 12 秒。

| 请求 | 比例 |
| --- | ---: |
| 发现页首屏 | 22% |
| 帖子详情 | 20% |
| 帖子搜索 | 21% |
| 评论首页 | 17% |
| 作者公开资料 | 18% |
| 点赞或取消点赞 | 1% |
| 创建评论 | 1% |

热门场景将详情和评论集中在 8 篇帖子上，公开资料集中在 10 位作者上，帖子搜索使用固定搜索词。分散场景让详情和评论遍历 5,000 篇帖子，公开资料分散到 800 位作者，帖子搜索使用随帖子变化的搜索词。两个场景都请求默认发现页首屏。

用 k6 以固定到达率运行。先短测定位档位。正式对照从对照组的最高通过档位起测，每档测量 60 秒，相邻档位间隔约 200 请求/秒。通过档位须连续取得两次合格结果。以下结果以重复通过的最高测试档位为准，适用范围为本次负载模型和测量窗口。

每档都须满足同一组约束。

- 全局 P95 低于 500 ms，搜索 P95 低于 800 ms，其余接口 P95 低于 100 ms。
- 全局错误率低于 1%，HTTP 503 比例低于 0.5%。丢失迭代不超过计划请求的 0.1%，完成请求达到计划请求的 99.8%。
- Elasticsearch 采样 CPU 峰值低于配额的 85%。所有容器合计 CPU 限流次数低于每分钟 100 次，无 OOM。
- 测量窗口内 Redis 淘汰键数无增量。HTTP 429 计入错误，并单独记录。

在至少一个场景的通过档位上升且成功吞吐增量超过重复测试波动，同时另一场景保持容量时，该期开关可进入下一期对照。每期使用当时已通过的上一轮配置作为关闭组。

## 真实依赖联调

| 阶段 | 结果 |
| --- | --- |
| 一期 | 详情、列表和搜索全命中时，MySQL 跳过点赞和评论计数。部分命中时只对缓存未命中的帖子 5000 分组统计，零计数可命中。重复点赞、取消点赞、4 条并发评论和无效 JSON 后回源均通过。24 次并发冷读合并为 1 次互动计数回源。 |
| 二期 | 热读 21 个候选执行 3 次 MySQL 查询和 3 次 Redis MGET。正文版本按批校验，正文全命中时无 MySQL 正文查询。两位访问者的点赞、收藏和关注保持各自结果。发帖、编辑、删帖、候选失效和第 20 条生成的游标检查通过。 |
| 三期 | 默认评论首页命中跳过评论列表 SQL。空页、后续页以及创建评论和删帖清理评论页与计数均通过。 |
| 四期 | 大小写别名共用规范化缓存键。命中时只读取访问者关系所需的数据。缓存值仅含公开字段。两位访问者的 `following` 和 `is_self`、更新资料后失效以及不存在的用户均通过。 |

切换真实 MySQL 的数据 epoch 后，四类缓存使用新键。旧计数和旧候选列表未用于新请求。单独关闭限流、停止隔离 Redis 后，五条读取路径仍返回预期结果。Redis 失效失败时，已提交的点赞和取消点赞仍成功。将四个分期开关全部打开并设置 `BACKEND_REDIS_DISABLED=true`，Redis 未新增键，五条读取路径均通过。

在四个新缓存全关和全开时，分别以同一身份发出 130 个连续请求。两组均返回 61 个 HTTP 200 和 69 个 HTTP 429。

- 二期真实 MySQL 恰好 20 篇帖子时无下一页，热读保持相同结果。
- 二期 1 个候选的热读也执行 3 次 MySQL 查询和 3 次 Redis MGET。
- 二期真实 MySQL 空列表无下一页，Redis 保留空页命中。
- 评论和公开资料缓存损坏后回源通过。6 个计数键在同一窗口过期，24 个并发首屏请求合并为 1 次分组统计。
- Redis 故障期间记录了 2 条提交后失效失败日志。

## 启用决定

| 阶段 | 对照组 | 热门档位变化 | 分散档位变化 | 判定 | 局部回退开关 | 实现提交 |

| 一期互动计数 | 候选版全关 | 1600 → 1600 | 1500 → 1300 | 有场景的通过档位低于对照，保持关闭 | `BACKEND_POST_COUNTS_CACHE_ENABLED=false` | `2de97212` |
| 二期发现页 | 候选版全关 | 1600 → 1200 | 1500 → 1300 | 有场景的通过档位低于对照，保持关闭 | `BACKEND_DISCOVERY_CACHE_ENABLED=false` | `2c11dc9f` |
| 三期评论首屏 | 候选版全关 | 1600 → 1600 | 1500 → 1300 | 有场景的通过档位低于对照，保持关闭 | `BACKEND_COMMENT_PAGE_CACHE_ENABLED=false` | `c6f63799` |
| 四期公开资料 | 候选版全关 | 1600 → 1600 | 1500 → 1500 | 通过档位与对照相同，保持关闭 | `BACKEND_PUBLIC_PROFILE_CACHE_ENABLED=false` | `3913eaa5` |

仓库中的四个局部开关均默认为 `false`。单机 Compose 环境修改当期开关后，重新创建 API 容器使配置生效。 [.env.example](../.env.example)

后端四期及 epoch 修正提交均通过 `make ci-check MODULE=backend/business`、`make ci-test MODULE=backend/business` 和 `make ci-build MODULE=backend/business`。Compose 配置检查通过。
