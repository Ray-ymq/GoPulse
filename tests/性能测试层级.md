# 性能测试层级

每个层级选择一个主工具，再使用必要的观测工具。单次测试不启用全部工具。

| 层级 | 主工具 | 观测或定位工具 | 重点 |
| --- | --- | --- | --- |
| API 与业务链路 | `k6` | 访问日志、`docker stats` | 吞吐量、p95/p99、错误率、业务结果 |
| Go 代码 | `go test -bench` | `pprof`、`benchstat` | CPU、内存、锁竞争、阻塞 |
| MySQL | `k6` 产生真实业务负载 | `performance_schema`、慢查询日志、`EXPLAIN ANALYZE` | SQL 延迟、连接池、锁等待、执行计划 |
| Redis | `k6` 产生真实业务负载 | `INFO`、`LATENCY`、`SLOWLOG` | 命中率、命令延迟、内存、连接 |
| RabbitMQ 与异步链路 | `k6` 产生写入事件 | 队列深度、unacked、消费速率、重试、死信 | Outbox、Worker、Indexer 的积压和恢复 |
| Elasticsearch | `k6` 产生搜索负载 | `_cluster/stats`、`_nodes/stats` | 查询延迟、写入延迟、堆内存、拒绝任务 |
| 容器与主机 | `docker stats` | `pidstat`、`vmstat`、`iostat`、`ss` | CPU、内存、磁盘、网络、连接数 |

## 执行顺序

1. 使用 `k6` 执行冒烟、基线、容量、压力、稳定性和突发流量测试。
2. 同时采集容器、主机和依赖组件指标。
3. 发现瓶颈后，使用对应层级的定位工具复测。
4. 修改代码或配置后，使用相同负载重新验证。

## 关键原则

- API 延迟与异步最终一致性延迟分开统计。
- 使用 p95 和 p99，不使用平均值作为唯一结论。
- 验证响应正确性、幂等性、限流和错误恢复。
- 使用独立测试环境和接近生产规模的数据。
