BACKEND / BUSINESS

社交业务，从请求到通知。

GoPulse 业务后端提供用户认证、资料、关注、帖子、评论、点赞、收藏、搜索和通知。此页汇总模块结构与操作入口，可直接在浏览器中打开。

Go 1.26MySQLRedisRabbitMQElasticsearch

Go module：github.com/Ray-ymq/GoPulse/backend。HTTP 接口以 OpenAPI 契约为准。本页为静态说明，不显示服务实时状态。

01 / 数据如何流转

业务 API→MySQL + Outbox→RabbitMQ→Worker / Indexer

业务写入 MySQL，并在同一事务中记录 Outbox 事件。API 进程中的分发器将事件发送到 RabbitMQ。业务 Worker 消费异步任务并生成通知；搜索 Indexer 消费搜索任务并更新 Elasticsearch 索引。

Redis 提供正文缓存和共享限流。设置 BACKEND_REDIS_DISABLED=true 时，正文缓存被禁用，限流配额按进程独立计算。

如何阅读业务包

HTTP 适配位于 internal/transport/http/handlers/。业务包位于 internal/modules/，按实际需要用 service*.go、repository*.go 和 model*.go 区分流程、数据访问和模型。

*_test.go 保存测试。带 integration 构建标签的测试需要单独准备依赖环境。cmd/ 负责启动和组装；具体业务实现位于 internal/。

03 / 准备与运行

运行前需自行准备 MySQL、Redis、RabbitMQ 和 Elasticsearch，并创建应用使用的数据库与账号。配置示例见根目录 .env.example。后端只读取进程环境变量，不会自动加载 .env。

在仓库根目录执行以下命令。配置值含有空格、$ 或其他 shell 特殊字符时，需先按 shell 语法正确引用。

set -a
. ./.env
set +a
cd backend/business

升级已有数据库前，先备份需要保留的数据。迁移 000021_remove_observability 会删除三张告警表；降级只能恢复表结构，不能恢复已删除的告警历史。

go run ./cmd/migrate validate
go run ./cmd/migrate status
go run ./cmd/migrate up

validate 只校验内嵌迁移文件，不连接数据库。status 查看数据库迁移状态。up 执行待应用的迁移。

完成迁移后，分别在三个已加载配置的终端中进入 backend/business/，执行下列命令。使用 Ctrl+C 停止进程。

常驻进程及默认监听地址
命令默认监听地址
go run ./cmd/serverAPI：127.0.0.1:8080
go run ./cmd/business-worker健康检查：127.0.0.1:19102

首次准备搜索索引时，在已加载配置的模块目录执行 go run ./cmd/search-reindex --if-missing。搜索别名已存在时，该命令跳过重建。需要主动重建时，执行不带 --if-missing 的命令。完整配置约束、恢复参数与角色维护操作见 模块 README。

04 / 验证与健康检查

在仓库根目录验证

make ci-check MODULE=backend/business
make ci-test MODULE=backend/business
make ci-build MODULE=backend/business

ci-check 检查格式并运行 go vet 和 lint；ci-test 执行带竞态检测的单元测试；ci-build 构建模块。

健康探针

  • /startup：初始化已完成。
  • /live、/health：进程存活。
  • /ready：初始化已完成、未进入退出阶段，且必要依赖和状态检查通过。

探针响应只包含 status。业务进程使用 internal/logging 输出 slog JSON 日志，通过 os/signal 接收退出信号。

Go CI 命令使用 .run/ci/go.work。单元测试与构建结果不能代替真实数据库、搜索和异步任务联调。单机部署入口为根 compose.yml，操作步骤见 部署说明。仓库不提供本地开发编排或压测工具。
