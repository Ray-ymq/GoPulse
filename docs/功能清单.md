# GoPulse 功能清单

按当前工作树的实际入口整理：用户端与管理端取各自路由与后端 `/api/v1` 注册，后台任务取各运行角色的处理分支，观测链路与交付运维取各组件的命令行与接口定义。

## 用户端功能

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 注册 | 页面 `/register`；`POST /api/v1/auth/register` | 创建账号并建立会话 |
| 登录 | 页面 `/login`；`POST /api/v1/auth/login` | 账号口令登录 |
| 登出 | `POST /api/v1/auth/logout` | 结束当前会话 |
| 会话恢复 | 页面 `/auth-recovery`；`GET /api/v1/users/me` | 会话失效时引导重新登录并回到原页面 |
| 查看与修改资料 | `PATCH /api/v1/users/me/profile` | 修改当前用户资料 |
| 用户主页 | 页面 `/users/:username`；`GET /api/v1/users/:username` | 展示用户信息与其帖子 |
| 我的帖子列表 | `GET /api/v1/users/:username/posts` | 按游标分页 |
| 关注与取关 | `PUT`、`DELETE /api/v1/users/:userId/follow` | 建立或解除关注关系 |
| 关注列表与粉丝列表 | 页面 `/me/following`、`/me/followers`；`GET /api/v1/users/me/following`、`/users/me/followers` | 两个方向的关系列表 |
| 关注流 | 页面 `/posts` 的 Following 页签；`GET /api/v1/posts/following` | 只看已关注用户的帖子 |
| 发帖 | 页面 `/posts/new`；`POST /api/v1/posts` | 带幂等键，重试不会重复发帖 |
| 帖子列表与详情 | 页面 `/posts` 的默认页签、`/posts/:postId`；`GET /api/v1/posts`、`/posts/:postId` | 游标分页，详情走缓存 |
| 编辑帖子 | 页面 `/posts/:postId/edit`；`PATCH /api/v1/posts/:postId` | 修改内容并刷新缓存与搜索索引 |
| 删除帖子 | `DELETE /api/v1/posts/:postId` | 永久删除并同步缓存与索引 |
| 命令上下文与结果 | `GET /api/v1/post-commands/context`、`/post-commands/result` | 客户端查询重试身份与最终结果 |
| 评论 | `POST`、`GET /api/v1/posts/:postId/comments` | 发表评论与评论列表 |
| 点赞与取消 | `PUT`、`DELETE /api/v1/posts/:postId/like` | 点赞状态随详情返回 |
| 收藏与取消收藏 | `PUT`、`DELETE /api/v1/posts/:postId/bookmark` | 收藏为私有列表 |
| 收藏列表 | 页面 `/bookmarks`；`GET /api/v1/bookmarks` | 查看自己的收藏 |
| 搜索 | 页面 `/search`；`GET /api/v1/search/posts`、`/search/users` | 帖子与用户两个页签 |
| 通知 | 页面 `/notifications`；`GET /api/v1/notifications` | 评论、点赞、关注的异步通知 |
| 通知已读 | `PATCH /api/v1/notifications/:notificationId/read` | 标记单条已读 |
| 开发状态页 | 页面 `/dev/status` | 本地查看前端与后端连通状态 |

## 管理端功能

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 总览看板 | 页面 `/admin/`；`GET /api/v1/admin/overview` | 业务与观测的关键状态汇总 |
| 指标查询 | 页面 `/admin/metrics`；`GET /api/v1/observability/metrics`、`/metrics/catalog` | 按目录查询指标，含可用指标清单 |
| 日志查询 | 页面 `/admin/logs`；`GET /api/v1/observability/logs` | 按时间与条件检索日志 |
| 事件查询 | 页面 `/admin/events`；`GET /api/v1/observability/events` | 查询采集与告警事件 |
| 告警规则管理 | 页面 `/admin/alerts`；`/api/v1/alerts/rules` 的增删改查与 `enable`、`disable` | 阈值、窗口、持续时间与来源配置 |
| 告警目录 | `GET /api/v1/alerts/catalog` | 可配置的指标来源与选择项 |
| 告警当前态与历史 | `GET /api/v1/alerts/current`、`/alerts/history` | 活动事件与历史事件 |
| 用户与角色管理 | 页面 `/admin/users`；`GET /api/v1/admin/users/:userId`、`PUT /api/v1/admin/users/:userId/role` | 查询用户并调整角色 |
| 审计事件 | 页面 `/admin/audit`；`GET /api/v1/admin/audit-events` | 管理操作留痕 |
| 插件管理 | 页面 `/admin/plugins`；`GET /api/v1/exporter-plugins`、`/catalog`、`/:pluginId` | 插件清单、目录与详情 |
| 插件安装与配置 | `POST /api/v1/exporter-plugins/install`、`/:pluginId/install`、`/:pluginId/connection-test`、`PUT /:pluginId/configuration` | 安装、连通性测试与参数下发 |
| 插件启停与更新 | `POST /api/v1/exporter-plugins/:pluginId/start`、`/stop`、`/update` | 控制采集进程生命周期 |

## 后台与异步任务

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 事务 Outbox 投递 | `server`、`business-worker` 内部循环 | 事务内落库，后台按租约投递到 RabbitMQ 并重试 |
| 通知生成 | `business-worker` | 处理 `comment.created`、`post.liked`、`user.followed` 生成通知 |
| 搜索索引增量 | `search-indexer` | 处理 `post.created`、`post.updated`、`post.deleted` 更新 Elasticsearch |
| 搜索索引初始化与重建 | `search-reindex`（Compose 的 `search-init` 服务） | `--if-missing` 建初始索引，恢复时按代际参数重建 |
| 数据库迁移 | `migrate` 的 validate、status、up 子命令（Compose 的 `migrate` 服务） | 启动前校验、查看状态并升级结构 |
| 超级管理员初始化 | `admin-role bootstrap --user-id`、`promote --username` | 确保存在超级管理员角色 |
| 告警规则评估 | `server` 的 platform 角色，受评估开关控制 | 按规则窗口与持续时间评估，产生或恢复事件 |
| 数据保留期清理 | `marshaller` | 按配置天数清理日志与事件 |
| 帖子详情缓存 | `server`（Redis） | 缓存公共投影，写操作后失效 |

## 观测链路

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 遥测消息摄取 | `POST /internal/v1/messages`（router） | 校验 Bearer 令牌与幂等键，写入 Kafka |
| 日志摄取 | `POST /internal/v1/logs`（monitor） | 组件日志进入观测链路 |
| Kafka 生产 | router | 用 franz-go 按主题投递 |
| 遥测消费与落库 | marshaller | 指标导入 VictoriaMetrics，日志与事件写入 Elasticsearch |
| 指标采集 | monitor | 周期抓取各 exporter 的 `/metrics`，超时与失败转为事件 |
| 插件运行时 | monitor 的 `/internal/v1/exporter-plugins` 接口 | 以子进程启停 exporter，参数由管理端下发 |
| 插件打包 | `monitor/cmd/plugin-package`；`make package-plugin` | 生成带清单与校验的插件归档，合同版本 2 |
| 六类采集器 | 各 exporter 的 `/metrics`、`/health` | redis、mysql、rabbitmq、kafka、elasticsearch、victoriametrics |
| 指标目录与输出 | componentmetrics | 统一指标命名与 Prometheus 文本输出，被多个组件复用 |
| 消费校验工具 | `router/cmd/verify-consumer` | 校验 Kafka 记录是否按预期投递 |
| 健康与就绪 | 各组件的 `/health`、`/ready` | 供 Compose 健康检查与验收使用 |

## 交付与运维

| 功能 | 入口 | 说明 |
| --- | --- | --- |
| 本机依赖启停 | `make deps`、`make stack-up`、`make stack-down`、`make stack-verify` | 启动或停止当前工作区拥有的依赖与栈 |
| 源码开发环境 | `make dev`、`make dev-observe`、`make stop` | 本机源码运行，观测组件按需加入 |
| 安装与升级 | `gopulse init`、`up`、`down` | 初始化环境、启停产品栈 |
| 状态与日志 | `gopulse status`、`logs`、`verify`、`doctor` | 查看运行状态、聚合日志与自检 |
| 备份与恢复 | `gopulse backup`、`restore` | 备份数据并在恢复时校验代际 |
| 候选包构建与发布 | `gopulse-package build`、`verify`、`promote`、`run`、`env`；`make package` | 构建不可变候选并校验后发布 |
| 发布清单 | Bundle 内的 manifest 与 SHA256、JSON Schema | 制品与运行时契约一并校验 |
| 插件发布 | `make package-plugin` | 生成 exporter 插件归档与校验文件 |
| 验收套件 | `gopulse-acceptance compose`、`business`、`observe`、`plugins`、`alerts`、`roles`、`pages`、`lifecycle`、`reconcile-accounts`；`make verify-*` | Compose、业务、观测、插件、告警、角色、页面与生命周期验收 |
| 原生集成与浏览器验收 | `make integration SCOPE=`、`make e2e SCOPE=` | 隔离作用域下跑集成与 Playwright 检查 |
| 模块检查 | `make` 的 check、lint、test、race、build（带 `MODULE=`）与 `check-all` | 按模块执行格式、静态检查、测试与构建 |
| 变更范围选择 | `ci/quality_scope.py` | 按与公共祖先的差异选择需要跑的检查 |
| 门禁与自动合并 | GitHub Actions 的 `quality-gates`、`auto-pr-merge` | 推送即跑矩阵并自动开 PR 合并 |
| 候选发布流程 | GitHub Actions 的 `release-candidate`、`cache-warm` | 构建发布候选与预热构建缓存 |
| 工具链固定 | `devtools/toolchains.json`；`make doctor`、`make bootstrap` | 校验并安装指定版本的工具链 |
| 容量与负载 | `loadtest` 的 `cmd/load`、`cmd/recipe` | 按 JSON 配方压测与生成数据 |
