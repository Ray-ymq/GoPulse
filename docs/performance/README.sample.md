# PT 测试固定流程（样版）

PT 测试用于测量指定测试条件下的业务容量、最大成功吞吐、过载表现和卸载恢复能力。

按以下顺序执行：固定测试条件 → 检查环境 → 建立基线 → 逐级加压 → 边界复测 → 持续负载验证 → 超载测试 → 整理结果。

连续加压、各轮独立复测、持续负载验证和超载测试结束后，均先执行卸载恢复，再开始下一组测试。

## 1. 固定测试条件

执行前确定并记录以下内容。同一组测试期间不得临时调整。

| 类别 | 必须确定的内容 |
| --- | --- |
| 测试目标 | 被测业务、测试范围、需要验证的问题 |
| 版本与部署 | 被测代码版本、未提交改动、服务与依赖版本、实例数量、部署位置 |
| 资源与配置 | CPU、内存、磁盘、连接池、并发预算、限流和超时配置 |
| 初始状态 | 数据规模、账号与权限、缓存状态、异步积压 |
| 工作负载 | 业务比例、访问分布、请求内容、账号数量、压测器并发能力 |
| 执行参数 | 起始请求率、加压步长、档位上限、预热时长、各阶段测量时长、复测次数 |
| 业务标准 | 成功判定、延迟与失败率阈值、实际请求率要求、异步处理要求 |
| 停止条件 | 吞吐平台判定条件、压测器能力边界、资源保护阈值、故障终止条件 |
| 恢复标准 | 恢复后的验证负载、业务与资源指标范围、积压要求、恢复观察时长 |

参数发生变化时，结束当前组并记录原因。调整后的结果单独统计。

## 2. 检查环境

1. 检查服务和关键依赖的运行状态。
2. 验证被测业务能够完成预期操作，包括权限检查和异步处理。
3. 检查测试数据是否足以支撑计划负载和时长。
4. 检查压测器的资源、连接和并发能力。
5. 检查指标与日志是否完整，确认各采集端的时间一致。
6. 记录初始资源占用、缓存状态和异步积压。
7. 核对自动停止规则，区分业务阈值和故障终止条件。

检查未通过时，先修复问题，再开始测试。数据耗尽、权限错误和压测器能力不足必须单独记录，不能直接归为被测系统的性能故障。

## 3. 建立基线

1. 使用已确定的起始请求率发送负载。
2. 完成预热，单独记录预热数据。
3. 在正式测量窗口内采集业务、资源和异步处理指标。
4. 检查实际请求率是否达到要求。
5. 检查业务指标是否满足基线标准。

基线未通过时，不得进入后续加压阶段。检查环境、数据、版本和负载设置，解决问题后重新验证。

需要降低起始请求率时，记录调整原因，重新建立基线。

## 4. 逐级加压

1. 基线通过后，按已确定的步长提高请求率。
2. 每档先预热，再执行正式测量。
3. 记录每档的实际请求率、成功吞吐、延迟、失败率、资源占用和异步积压。
4. 首次不满足业务标准时，记录最后通过档和首次未通过档。
5. 在未触发停止条件的情况下继续加压，观察成功吞吐和退化趋势。
6. 达到停止条件后，停止增加负载，记录结束原因。

同一组连续加压期间保留前一档的缓存、数据和积压。不得在档位之间清理数据、排空积压、重启服务或调整配置。

超过业务阈值用于标记退化，不自动终止后续超载观察。出现 429、503 或单次健康检查失败时，结合持续时间、成功吞吐和依赖状态判断是否触发故障终止条件。

压测器无法达到目标请求率时，记录其资源与并发状态。不能把未成功施加的目标负载作为被测系统的容量边界。

## 5. 边界复测

只有取得最后通过档和首次未通过档时，才执行边界复测。

1. 在最后通过档和首次未通过档之间选择更小的加压步长。
2. 每轮独立复测前，将环境恢复到已确定的初始状态。
3. 按相同的预热、测量时长和业务标准执行复测。
4. 完成已确定的复测次数，记录每轮结果和波动。
5. 根据复测结果更新容量区间。

尚未找到首次未通过档时，只记录已验证通过的负载范围，不给出容量上界。尚未取得有效通过档时，不给出已验证的业务容量。

## 6. 持续负载验证

1. 根据逐级加压或边界复测结果，选择需要验证的通过档。
2. 将环境恢复到已确定的初始状态。
3. 完成预热后，按已确定的持续时长保持负载。
4. 观察成功吞吐、延迟、失败率、资源占用和异步积压的变化。
5. 检查整个测量窗口是否满足业务标准。

测试期间不得清理积压或调整配置。短时通过的档位如果在持续负载下退化，应分别记录两种结果。

通过结论只适用于实际验证的时长，不据此推断更长时间内的表现。

## 7. 超载测试

1. 将环境恢复到已确定的初始状态。
2. 施加超过已验证业务容量的负载。
3. 按已确定的加压规则和持续时长执行测试。
4. 观察拒绝、超时、成功吞吐下降、延迟增长、资源耗尽和积压增长。
5. 达到停止条件后，停止加压并保存现场指标和日志。

应用或关键依赖崩溃、OOM、非计划重启、非预期的数据丢失或一致性异常，以及达到预先确定的资源保护阈值，均属于故障终止条件。任何阶段发生其中任一情况时，立即停止加压并保存证据。

达到档位上限只表示本轮测试结束。压测器先达到能力边界时，明确记录“被测系统极限尚未测出”。

## 8. 卸载恢复

1. 停止当前组的加压流量，记录卸载时间。
2. 在已确定的观察时长内，按恢复标准验证业务和依赖状态。
3. 记录延迟、成功率、资源占用、积压量和最老积压年龄。
4. 达到恢复标准时，记录恢复耗时和残留影响。
5. 观察结束仍未达到恢复标准时，记录“观察窗口内未恢复”。

观察期间不得主动清理积压、重启服务或调整配置。需要人工处理时，先保存现场，再记录处理动作、时间和处理后的验证结果。

进程存活、健康检查通过和业务链路恢复必须分别判断。人工处理后的恢复不能记为自行恢复。

## 9. 整理结果

1. 记录测试条件、各阶段起止时间和时区。
2. 汇总每档的目标与实际请求率、请求数、成功吞吐、未发出的迭代数。
3. 汇总总体及成功请求的 P50、P95、P99，并分别记录拒绝、其他非预期响应、超时和传输错误。
4. 汇总压测器、应用和依赖的资源指标，以及异步提交量、处理量、积压量和最老积压年龄。
5. 记录业务容量区间、持续负载验证结果、过载表现和卸载恢复结果。
6. 列出异常证据、人工操作、测量限制和仍需验证的问题。

成功吞吐只统计达到业务目标的请求。异步吞吐按实际事件统计，不用请求量或业务比例推算。

结论必须区分达到业务标准的负载、观测到的最大成功吞吐和最高实际施加的负载。瓶颈判断应说明证据；尚未验证的原因应标为推测。

整理结果时，不得包含密码、令牌或其他敏感信息。
