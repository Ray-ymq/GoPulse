01删除后的项目状态

本文区分实际存在的源码、尚未清理的配置引用和需要自行准备的运行环境。源码入口存在，不代表当前可以成功构建或启动。

runtimekit 已删除，业务依赖尚未解除

当前工作区已删除 backend/runtimekit/ 源码与 go.mod。根 Makefile 仍注册该模块，业务 go.mod 仍通过 replace … => ../runtimekit 引用它。

API、Worker、Indexer、配置、日志和 HTTP 等代码仍导入 runtimekit。当前本地依赖不完整，不能将后端描述为可直接构建的完整系统。后续需要恢复该库，或迁移其能力并清理引用；本文仅记录此状态。

已移除的工程资源

部署配置、本地开发编排、tools/devtools/ 和 tools/perflab/ 已移除。当前没有可引用的 Docker、Compose、Kubernetes 或 Nginx 部署配置，也不再提供原来的压测执行入口。

已移除的产品能力

管理前端、平台 API、插件管理、Monitor、Marshaller、Kafka、VictoriaMetrics、日志和事件查询及告警已移除。业务说明同时记录了指标埋点、采集任务、指标接口和链路追踪的移除。

02六个逻辑层

分层用于解释职责，不代表六个独立服务或六级目录。业务包在同一个 Go 模块中组合 Handler、Service、Repository 和模型。

L1

用户交互层

frontend/web/src

Vue 页面和组件展示业务。Vue Router 管理路由与登录检查；composables 管理会话和社区状态；Fetch 封装 HTTP 请求。界面采用纸墨主题。

Vue 3TypeScriptVue Router
L2

HTTP 接入层

internal/http

Gin 注册路由与中间件，处理会话认证、授权、同源写保护、限流和请求日志。接口以 OpenAPI 描述。开发代理由 Vite 提供；生产代理需自行配置。

GinOpenAPI 3.1Cookie
L3

业务应用层

internal 下的业务包

认证、用户、关注、帖子、评论、点赞、收藏、搜索与通知按业务包组织。Service 执行输入校验和业务规则。businessstate 管理数据 epoch 与恢复相关状态。

Service业务模型businessstate
L4

数据访问层

Repository / platform

Repository 使用显式 SQL 和事务读写 MySQL。platform 管理依赖连接；缓存与搜索适配器连接 Redis 和 Elasticsearch。

database/sqlRepository客户端适配

异步协作层

Outbox / Worker / Indexer

业务事务保存 Outbox 事件。API 内的 Dispatcher 发布消息；业务 Worker 处理异步任务和通知；搜索 Indexer 更新索引。消息拓扑包含重试与死信处理。

04核心数据链路

以下描述保留源码中的调用设计；当前缺失的 runtimekit 依赖仍需解决，才能验证完整运行链路。

读取与会话

Vue / Fetch→Gin / Service→Repository
  1. 浏览器向同源 /api/v1 发送请求；开发环境由 Vite 代理到后端。
  2. 后端校验 Cookie 会话，并按接口执行授权与请求保护。
  3. 仓储读取 MySQL；启用 Redis 时，帖子正文可使用缓存和有界缓存重建。

事务与异步处理

MySQL + Outbox→Dispatcher→RabbitMQ
  1. 以帖子写入为例，同一数据库事务保存业务事实与 Outbox 事件。
  2. API 内 Dispatcher 领取记录并发布消息，使用租约、超时和重试控制。
  3. Worker 处理业务任务与通知；Indexer 消费搜索事件并更新索引。

数据库提交与消息消费分属不同阶段，不构成跨 MySQL、RabbitMQ 和 Elasticsearch 的单一原子事务。

搜索与写入恢复

Search API→Elasticsearch
  1. 搜索 Service 查询索引并处理可见性；索引可能晚于业务事务提交。
  2. search-reindex 按数据库事实重建索引。
  3. 前端发帖使用成对的幂等键与 data epoch；网络中断后保留原身份，以便查证或重试。

评论接口没有幂等键。发送结果不明时，界面提示先刷新并核对评论。

06开发与验证入口

前端

安装依赖后，可在独立终端启动 Vite。完整业务联调还需要可用的后端与基础服务。

make -C frontend/web install
make -C frontend/web dev
make check MODULE=frontend/web
make test MODULE=frontend/web
make build MODULE=frontend/web

浏览器流程验证：在 frontend/web 执行 npm run test:e2e。运行前需安装 Playwright Chromium 及所需系统库。

后端

先补齐或迁移 runtimekit 依赖，再执行模块验证。运行前需自行准备 MySQL、RabbitMQ、Elasticsearch，以及配置启用的 Redis。

make ci-check MODULE=backend/business
make ci-test MODULE=backend/business
make ci-build MODULE=backend/business

这些命令是保留的验证入口，不代表当前已经通过。本次整理不启动业务进程或执行数据库迁移。

迁移 000021_remove_observability 删除三张告警表。升级前应备份需要保留的历史；降级只能恢复表结构，不能恢复已删除数据。docs/performance/ 中的历史资料不作为当前压测入口。
