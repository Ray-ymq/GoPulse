## 目标架构

两篇设计共同负责项目的目标架构，已采纳为设计依据；其中的目标能力仍需通过实施与验收才能成为产品事实。

| 设计 | 负责范围 |
| --- | --- |
| [高并发架构设计](<GoPulse 高并发架构设计.md>) | 业务模块、事实源、一致性、异步执行、容量与故障边界 |
| [可观测架构设计](<GoPulse 可观测架构设计.md>) | 观测数据、控制与查询、诊断实验，以及两篇共用的身份和环境资源契约 |
| [目标架构图解](../dev/design/diagrams/target-architecture/README.md) | 整体、业务、可观测三张目标图；以两篇设计正文为准 |
| [目标架构落地大纲](../dev/design/GoPulse-目标架构落地大纲.md) | 两篇设计的下级展开：现状差距、详细设计专题、依赖、迁移和验收方向 |

共享边界的变更须同步两篇设计。目标设计不自动改写已分配批次的版本、分支、验收合同或实际停点。
