# PT 测试指标汇总

日期：2026-10-22。

本文汇总已核对的 PT 历史会话、测试一至测试六方案与报告中的测量需求。表格列出指标及其范围；Redis 对照、深入诊断和 pprof 按测试场景选用，具体采集能力以对应工具为准。

## 1. 业务表现与负载有效性

衡量实际施加了多少压力、完成了多少有效业务，以及失败和延迟如何变化。总体与成功请求的延迟分开，各业务路由分别统计。

| 指标类别 | 具体指标 |
| --- | --- |
| 请求速率 | 目标 RPS、实际开始请求 RPS、实际完成请求 RPS、有效成功 RPS |
| 请求计数 | 开始数、完成数、成功数、失败数、最终未完成数、成功率、失败率 |
| 迭代丢弃 | dropped iterations 数量及比例 |
| 响应延迟 | 全部请求与成功请求的 P50、P95、P99；各路由对应分位数 |
| 错误分类 | 429、500、503、其他非预期响应及 error_code；客户端超时、传输错误、停压取消 |
| 首次失败 | 发生时间、阶段、档位、路由、状态码、原因、已运行时长 |
| 持续稳定性 | 每秒/每分钟吞吐、错误率、延迟；异常窗口及持续时间、积压增长趋势 |
| 负载真实性 | 实际业务比例、有效读写数、语料剩余量；删除成功 204 与已不存在的 404 数量 |
| 健康检查 | /live、/ready 等检查的成功率、耗时、连续失败时长；与真实业务可用性分别判断 |

## 2. 资源与应用保护

资源指标覆盖应用、MySQL、Redis、RabbitMQ、Elasticsearch、前端、k6 和采集进程。各实例分别统计，应用连接池按 api/outbox/probe 等用途区分。

| 指标类别 | 具体指标 |
| --- | --- |
| CPU | 实际配额、平均使用率、采样峰值、配额利用率；100% 对应的核数口径 |
| CPU 节流 | 调度周期数、节流周期数、节流周期比例、累计节流时间、节流时间比例 |
| 内存 | 实际上限、当前用量、窗口均值和峰值、持续增长趋势、OOM/OOM kill；RSS、cgroup 内存及可回收文件缓存分别区分 |
| 进程与容器 | 进程数、退出状态、崩溃、非计划重启、容器身份变化 |
| 主机资源 | CPU、系统负载、可用内存、swap、OOM、磁盘剩余空间 |
| 磁盘与网络 | 磁盘读写次数、字节数、耗时、繁忙程度；网络收发量、错误、丢包 |
| 压测器 | VU 数、CPU、内存、网络、指标时间序列数量；是否先达到发压能力上限 |
| HTTP 并发 | 当前及峰值 in-flight、并发上限、全局准入拒绝数 |
| 资源预算与限流 | 各类预算拒绝数及原因；限流放行、拒绝、不可用次数，按策略和运行模式区分 |
| 应用数据库操作 | 各操作次数、耗时、失败数及原因 |
| 应用连接池 | 各池上限、已打开连接数、使用中连接数；等待次数、累计及平均等待时间 |
| 多实例分配 | 各 backend 请求分布、各 worker/indexer 实际处理量及在途消息数 |

## 3. MySQL 诊断

通过连接、SQL、事务、锁和 I/O 定位业务退化。汇总指标与失败瞬间的阻塞现场配合分析。

| 指标类别 | 具体指标 |
| --- | --- |
| 可用性 | 独立新连接执行 SELECT 1 的成功率、耗时、失败阶段/原因、连续失败时长；Uptime、启动时间、重启次数 |
| 连接与线程 | 当前/峰值连接数、连接上限、活跃线程、新建连接速率、连接失败、异常断开、线程创建数 |
| 基础 SQL | 查询次数及速率、慢查询数、SELECT/INSERT/UPDATE/DELETE 次数 |
| SQL 摘要 | 按 digest 统计执行次数、累计/平均耗时、错误数、扫描/返回行数、临时磁盘表数、未使用索引次数 |
| 参数化执行 | Prepare、Execute、Close stmt 等事件的次数、累计耗时、错误数 |
| 提交与回滚 | COMMIT 次数、累计/平均耗时；ROLLBACK 次数；完整事务吞吐与事务持续时间需使用对应事务统计 |
| 事务状态 | RUNNING/LOCK WAIT/COMMITTING/ROLLING BACK 事务数；最老年龄、最长锁等待、锁定/修改行数 |
| 全库行锁 | 等待次数、累计等待时间、当前等待数、死锁数 |
| 热点行锁 | 按库/表/索引统计等待事务数、阻塞事务数、最长等待 |
| 阻塞现场 | 等待方/阻塞方事务及线程 ID、事务开始时间和年龄、SQL、锁对象、模式、数据、阻塞关系；事务分段耗时 |
| 元数据锁 | 对象、锁类型、PENDING/GRANTED 状态、持有者、等待者 |
| 错误与慢语句 | 锁等待超时、死锁、查询中断及其他错误码；慢语句/错误历史及时间 |
| Buffer Pool | 容量、数据量、脏页、总页/空闲页、逻辑读/物理读、命中率、等待空闲页次数 |
| 临时表与 Undo | 内存/磁盘临时表数、Undo 历史长度、Undo 槽位使用量 |
| Redo | 容量、当前/checkpoint LSN、checkpoint age、日志等待、待写入/待同步数量 |
| 文件 I/O | redo/binlog/数据文件的读写次数、字节数、累计耗时；misc 次数/耗时；观察到的 sync 事件及耗时 |
| 内部等待 | mutex、condition、rwlock、sxlock 等事件的次数及累计耗时 |
| 表与索引访问 | 按表/索引及 fetch/insert/update/delete 统计次数和累计耗时 |

## 4. 异步链路

衡量事件从提交、发布到最终应用的处理能力。消息确认、Outbox 落库和业务投影完成分别统计。

| 指标类别 | 具体指标 |
| --- | --- |
| 事件吞吐 | 实际提交、发布确认成功/失败、Outbox 标记 published、消费、最终应用完成的数量及速率 |
| 完成延迟 | 事件从提交到业务投影完成的延迟；搜索更新、删除的生效延迟 |
| Outbox 操作 | claim/cleanup 次数、成功/失败、耗时分布；清理候选数、删除数 |
| Outbox 积压 | pending/leased 等状态数量、最老积压年龄、增长/排空速率 |
| 消息队列 | 各队列 ready/unacked、在途消息、重试、重复处理、parked 数量 |
| RabbitMQ 专项 | 实际消息速率、消息大小、队列数量、发布阻塞及内存水位、积压恢复速度 |
| 异步预算 | 全部 epoch 的 open_requirements、parked_messages；保留组数/字节数、扣账异常 |
| 历史规模 | 已发布 Outbox、commands/requirements 等记录规模、数据/索引占用、保留量增长及清理效果 |

## 5. 缓存与 Redis

同时衡量缓存使用情况和数据库减负效果。历史讨论涉及冷读、热点重复读、Redis 开关及 TTL 对照；Redis 开关还会改变限流实现，对照结果需保留这一条件。

| 指标类别 | 具体指标 |
| --- | --- |
| 应用缓存 | 命中数、未命中数、命中率；回源次数/耗时；缓存写入成功/失败数 |
| 缓存重建 | 在途重建数、当前/已注册 waiter、重建拒绝数 |
| 数据库减负 | 命中、未命中、缓存不可用路径的 SQL 次数、扫描量、查询耗时、连接等待；相同负载下的变化 |
| Redis 组件 | CPU、内存及上限占比、连接数、命中/未命中、淘汰、命令延迟；复制和持久化状态按部署选用 |
| 缓存对照收益 | 命中率变化、回源减少量、详情失败率、Redis 内存、缓存写失败、数据库负载、持续成功吞吐 |

## 6. 数据正确性与恢复

按资源 ID 或请求路径核对真实业务结果，跨窗口请求单独统计。停压后的业务探测遵循对应方案，PT6 采用只读恢复观测。

| 指标类别 | 具体指标 |
| --- | --- |
| 写入正确性 | 新建/更新/删除的实际结果；资源 ID、作者、内容、revision；点赞/书签/关注最终状态 |
| 一致性异常 | 缺失行、内容不匹配、无对应请求的新建行、孤儿行、HTTP 结果与数据库事实不一致数量 |
| 搜索正确性 | 创建/修改/删除最终结果；applied、重复、重试、parked 数量；旧版本覆盖异常 |
| 窗口边界请求 | 窗口前开始但窗口内完成、窗口内开始但窗口后完成的请求数及核对结果 |
| 自然恢复 | 观察时长、实际恢复耗时、资源回落情况、残留积压/最老年龄、队列及全部 epoch 预算是否归零 |
| 业务恢复 | 方案允许的业务探测成功率及耗时；数据库可用、进程存活、真实业务恢复分别判断 |
| 人工干预 | 是否需要干预、操作内容、时间、干预后恢复耗时 |

## 7. 采集质量与按需剖析

采集完整性决定证据能否支持结论，诊断开销也需计入资源。pprof 按需启用。

| 指标类别 | 具体指标 |
| --- | --- |
| 采集状态 | 各采集器启用/成功状态、失败次数、耗时、心跳、退出状态、实际采样数 |
| 证据完整性 | 缺样、采样间隔、窗口边界覆盖、截断、计数重置、序列缺失、digest 丢失 |
| 采集配置 | Performance Schema、consumers、instruments 的启用及计时状态 |
| 历史覆盖 | 事件读取范围、时间域、缓冲区覆盖限制、读取游标推进状态 |
| 采集开销 | 采集进程 CPU/内存、单次查询耗时、诊断对业务的影响 |
| 按需 pprof | CPU 热点、heap、goroutine、block、mutex；采样配置及时间范围 |

## 8. 容量结论与比较条件

容量结论由前述指标共同支持。短时通过、持续容量、最大成功吞吐和最高施加负载分别表述。

| 类别 | 具体内容 |
| --- | --- |
| 通过与停压 | 最后通过档、首次异常/停压档、负载是否通过、诊断是否完整、停压原因 |
| 业务容量 | 达标负载区间、测量时长、持续测试结果及适用条件 |
| 吞吐与过载 | 最大有效成功吞吐、最高实际负载、吞吐平台、拒绝/延迟/积压变化 |
| 故障边界 | 业务失稳、数据库持续不可用、进程崩溃的边界与证据 |
| 恢复与限制 | 自然恢复结果、人工干预、压测器/采集器是否先受限、未验证事项 |
| 比较条件 | 代码及工具版本、部署角色和副本、实际配额、连接池、限流和超时、数据快照和 epoch、缓存初态、历史积压、业务比例、VU、实际测量窗口 |

统计口径：预热、正式测量和恢复分开；RPS 按实际窗口时长计算，累计计数取窗口增量。SQL 累计耗时不等于 CPU 时间，文件 misc 不等于 fsync，锁快照条数不等于锁事件次数。采集缺失不能当作 0；健康检查通过不能代替业务恢复证据。历史常用的 1% 错误率与 PT6 的首败停压分别按对应方案执行。
