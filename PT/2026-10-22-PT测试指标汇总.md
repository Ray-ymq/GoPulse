# PT 测试指标汇总

日期：2026-10-22。

本清单优先依据 Codex 历史会话，再核对 PT1～PT6 方案、报告和当前采集说明。每个指标单独一行，固定使用英文名称，并列出单位和中文含义。这是测量需求清单，不表示每轮测试或现有工具已经覆盖全部指标。

名称用于报告展示，不直接替代 Prometheus 指标标识符。相同指标通过阶段、档位、路由、实例、连接池、队列、状态等维度区分；例如 `Overall P95` 和 `Successful Request P95` 分开统计，`CPU Usage` 按 MySQL、Backend、k6 等实例分别报告。

## 6. 数据正确性与恢复

核对资源 ID、作者、内容、revision，以及点赞、书签、关注的最终状态。停压后的业务探测按对应方案执行；PT6 只读恢复观测不能证明完整读写业务已恢复。

| Interaction State Mismatch Count | count | 点赞、书签、关注最终状态不匹配数 |
| Search Apply Count | count | 按 applied/重复/重试/parked 结果统计搜索处理数 |

| Cross-Window Request Count | count | 按窗口前开始且窗口内完成、窗口内开始且窗口后完成分别统计请求数 |
| Recovery Observation Duration | s | 停压后实际恢复观测时长 |

跨窗口请求单独核对，不直接计入窗口内写入差额。恢复期间继续观察资源回落、队列排空和全部 epoch 预算。人工操作另存内容、时间及结果；进程存活、数据库可用和真实业务恢复分别判断。观察结束仍未满足恢复标准时，记录“观察窗口内未恢复”，不将观测时长当作恢复耗时。

## 9. 统计口径、比较条件与依据

- 预热、正式测量、恢复分开；速率按实际窗口时长计算；累计计数取窗口增量。分母为零或证据缺失时不计算比率、均值。
- 请求开始、完成、成功采用各自时间边界；跨窗口请求另列。未完成请求没有完整响应耗时，不能假定延迟分位值已覆盖这些请求。
- SQL 累计耗时不等于 CPU 时间，文件 misc 不等于 fsync，热点锁快照计数不等于锁等待事件数。独立探针通过不等于业务恢复。
- 性能阈值和停止条件按本轮方案执行；历史常用的 1% 错误率阈值与 PT6 首败停压规则不得混用。
- 比较时固定并记录代码及工具版本、部署角色和副本、实际资源配额、连接池、限流和超时、数据快照和 epoch、缓存初态、历史积压、业务比例、账号及 VU、测量窗口。
- 环境说明保留 CPU 指令集及主频、OS/虚拟化版本、swap、磁盘介质和网络条件。首次失败另存时间、阶段、档位、路由、状态码和原因；停压原因、人工干预及未验证事项单独记录。
