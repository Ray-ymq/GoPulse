## 3. 关键依据及判断边界

### 实例身份是实际缺口，日志关联不是从零建设

`monitor/internal/metrics/collector/components.go` 逐端点采集，但调用 `NewComponent` 时只传组件 ID；
`monitor/internal/metrics/envelope/envelope.go` 将 `target_id` 设为组件级固定值。
Marshaller 验证和转换、Backend 固定目录查询也沿用这个合同。
因此 A 必须贯通这些边界，不能只给抓取器加一个标签。
现有 `backend/internal/logquery/logquery.go` 已有 Trace/Span/业务事件关联字段，
OTel SDK 也已接入；产品增量在受限持久查询和管理端诊断体验。

### Trace 选择服务当前规模

[Jaeger 官方 API 合同](https://www.jaegertracing.io/docs/2.21/architecture/apis/)区分稳定 QueryService v3 与内部 UI API。
[Badger 文档](https://www.jaegertracing.io/docs/2.21/storage/badger/)明确本地持久化与单节点边界。
选择同进程采集/查询、独立持久卷，可减少新增外部状态服务；这是依据文档作出的架构取舍，
本次没有验证 GoPulse 镜像集成、磁盘行为或吞吐。
[Jaeger Elasticsearch 文档](https://www.jaegertracing.io/docs/2.21/storage/elasticsearch/)公布的支持范围不能证明仓库现有 ES 9.5.2 兼容，
但也不据此宣布已经发生不兼容故障。

### Kubernetes 首次交付有明确限制

[NetworkPolicy](https://kubernetes.io/docs/concepts/services-networking/network-policies/)需要相应网络实现支持；
私有 Service 地址不能代替策略或服务授权。
[Deployment Recreate](https://kubernetes.io/docs/concepts/workloads/controllers/deployment/)、
[StatefulSet 强删](https://kubernetes.io/docs/tasks/run-application/force-delete-stateful-set-pod/)和
[RWO 卷访问模式](https://kubernetes.io/docs/concepts/storage/persistent-volumes/)均不能单独构成无条件跨节点 fencing。
因此首次交付保留 Monitor 单实例与既有所有权保护，未知所有者先停止替换；不追加分布式控制面。
集群、CNI、存储和设备资源须在 B 实施前冻结并验证，不能预先宣称所有集群可用。

### 通知伸缩只作用于明确业务边界

现有 Worker runtime 逐条处理消息，prefetch 增加在途缓冲；RabbitMQ Exporter 汇总整个固定 vhost。
总纲选择 KEDA 直接读取通知主队列 `gopulse.business-worker.v1`，先测手动扩展再冻结自动策略。
语义依据 [KEDA 2.21 RabbitMQ scaler 官方文档源](https://github.com/kedacore/keda-docs/blob/main/content/docs/2.21/scalers/rabbitmq-queue.md)与
[KEDA 部署伸缩](https://keda.sh/docs/2.21/concepts/scaling-deployments/)。
控制正确性、业务正确性和性能收益分别表达，不能互相替代。
