## 3. 实施范围与真实数据约束

1. 调整 `admin-frontend/src/components/AdminLayout.vue`、`styles.css` 和必要共享组件，统一导航、面包屑、间距、图标、卡片与响应式布局。
2. 更新 `DashboardView.vue`、`ObservabilityMetricsView.vue`、`ObservabilityLogsView.vue`、`AlertsView.vue`、`ObservabilityExportersView.vue`。延续既有 API、路由、查询、分页/游标、配置和生命周期流程。
3. 实施时逐页记录参考区域到现有 DTO 的映射。统计注明全量、当前页或时间窗口口径；缺失数据显示 unknown/不可用，不伪装为 0、healthy 或真实趋势。
4. 示例中的 CPU/内存、版本、运行时长、同比、静默规则、关联 Trace、历史版本、连接测试、批量操作或安装操作，只有现有 API 明确支持才呈现为可用能力；否则隐藏或以明确说明的等价区域代替，不新增后端能力凑图。
5. Logs 详情与 Alerts 详情使用当前真实数据；严重程度与生命周期状态分别展示，不把 Warning 当作不存在的后端状态。保持现有规则、告警处理与审计流程。
6. Exporter 的 Secret 只沿用现有安全输入合同，不回显历史 Secret，不提供明文显隐；目标地址、标签与错误信息沿用既有脱敏边界。
7. 顶栏搜索、通知数、环境标签均不得伪造。保留统一登录、返回社交、退出、角色撤销分流和同源请求。
8. Events、用户角色、审计及告警规则等直接受共享壳层影响的页面保持可用。

不修改 Backend、API、Schema、消息处理、Compose 或 release 合同；不运行运行时收口、Migration、全产品韧性、跨架构或 Kubernetes 验收。

## 4. 执行顺序

1. 限时读取直接受影响的页面、DTO 和测试，列出五页数据映射与本轮相对 `1.14.1` 的差异。
2. 先调整共享壳层，再逐页完成展示与已有操作，保留部分失败、空状态和权限拦截。
3. 只增加或调整直接证明本批变更的测试：代表性选择/详情成功与失败、告警原有操作或变更的安全边界；不开展覆盖率扩张。
4. 运行最小受影响包检查；最终 diff 执行以下固定门禁一次，记录五页视觉对照和已接受的 API 差异。
5. 全部完成后写同名实施记录，更新受管版本元数据至批次目标并提交；本次规划准备不执行此版本升级。

## 5. 批次验收标准

### 视觉与交互

- 五页桌面截图与对应五张基准逐页人工对照；侧栏、顶栏、标题、统计卡、表格/图表和列表详情层级一致。差异仅来自真实 DTO、已有 API、可访问性及响应式约束，并在实施记录列出。
- 查询、刷新、时间范围、列表选择、分页/加载更多、日志详情、现有告警处理和 Exporter 生命周期/配置操作按现有合同工作，无假按钮或示例硬编码。
- loading/empty/partial/error/unauthorized 可辨识；长字段不挤出操作；未知值不伪装为正常状态。

### 直接回归与安全

- 超级管理员可正常使用五页；普通用户不得挂载管理页面或发出管理 API 请求。统一登录、返回社交、退出和角色撤销不回退。
- Events、用户角色、审计和现有告警规则/处理入口可用；浏览器请求同源，生产 bundle 不包含参考图、示例内部地址或凭据。
- 详情、复制、配置及错误展示不绕过现有脱敏与 Secret 合同。

### 响应式与可访问性

- 在 `1440 × 1000`、`768 × 1024`、`390 × 844` 检查导航、查询和详情。页面不产生不可控水平滚动；宽表可局部滚动，窄屏详情可关闭并返回列表。
- 键盘可到达导航、筛选、行选择、详情关闭和主要操作；heading/label/focus/status 正确，状态不只依赖颜色，遵循减少动态偏好。

明确完成条件：全部验收与固定门禁通过、无阻断问题、同名真实实施记录已完成、根 VERSION 及受管元数据为 `1.14.2` 且实现提交已创建。仅创建分支或计划不满足完成条件。
