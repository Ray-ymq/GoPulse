# 昂贵验收的成本与接续

本规则用于昂贵构建、真实系统验收和长时实验。普通代码、规则和文档任务无需单独建立时间台账。
已分配合同里的预算、停止条件和测量窗口继续有效；本文不追溯修改既有验收。

## 开工前写进已有实施方案

- 明确结果、固定门禁、环境和候选。估算准备、构建、测量、诊断及清理总成本，约定有限上限与停止点。
- 长时实验列出单元数量及预热/测量/恢复时间；窗口由验证目标决定，不能用短探针代替。
- 未知入口先做最低层预检。实现、诊断和正式实验分别记录，避免在完整矩阵中开发工具。

## 执行与失败

- 重试沿用原成本与候选记录，开始昂贵步骤前确认剩余预算足够执行和清理。
- 基础设施失败先停止整组，重现最小边界、修正原因并通过直接检查后，再运行受影响门禁。
- 同候选、相关输入和环境未变的成功检查继续有效。改动记录其影响，原始回执不能编辑或换绑。
- 到约定上限、诊断无法推进或用户停止时，有界清理本次资源，保存通过/失败/未开始、原始证据与剩余工作。
- 未完成不作完成提交。继续需要具体剩余方案和用户明确指令；规划修订不自动恢复暂停验收。

## 冻结候选的接续

正式矩阵使用已提交 revision 的固定源码与制品，期间不替换 manifest 或同名标签。
记录候选、配置、工具与环境身份；当前工具支持恢复时只执行仍有效的未开始项。
不支持恢复时如实说明重新执行的范围和成本，不手工拼接回执。
日志和进度记录自身不使未变的候选失效；相关应用、验证或发布输入改变后，重验受影响集合。

## 已取消 Phase 20 后续批次的历史事实

2026-10-05 按用户要求，Phase 20 仅保留 01～04，在 `2.2.4` 结束；原 05、06 已取消。
本节保留此前已观察到的失败与成本约束，不再提供当前执行或自动接续入口。
范围调整见[Phase 20 总实施方案](../imple/Phase-20/Phase-20-总实施方案.md)。
未来若沿用这些未完成工作，须由新方案明确分配，保留已有成本、诊断次数与失败证据。

2026-10-02 只读检查发现：05 的实现分支已有多次采样/编排/证据接口修复；私有历史根
`gopulse-phase20-05-20261001` 包含 13 份 incomplete 的 budget.json，另有多个候选的
preflight 失败回执。它们是失败尝试，不是必须重复的有效样本；不能仅凭提交时间推算
准确的 15 小时分项，准确分项需依据执行台账。

已观察到的错误包括采样器缺少 set_load_pid/failure、诊断模块缺少 read_jsonl、故障容器
无法定位和 marker observer 内存上限。预算 JSON 虽登记 execution_max_seconds /
candidate_build_max_seconds / b03_max_seconds，检查时预算与收口入口没有使用这些字段
建立统一累计 deadline；多个 subprocess timeout 不构成整份文件的时间上限。

这些事实属于取消前的历史记录，原验收结果仍以各候选回执为准。未来执行保护的落地应证明：
阶段和子进程共享剩余预算、跨启动保留累计耗时、超时停止新请求并有界收尾、回执保存
真实失败分类，以及仅恢复身份有效的未开始单元。实现此能力前不能称之为“已强制限时”。
