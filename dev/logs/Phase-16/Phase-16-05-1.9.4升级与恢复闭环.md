拆分计划 §3.1 要求 fixture 至少包含旧版运行产生的告警和审计事实，同时禁止人工构造
数据库最终状态。锁定来源不提供对应的新产品数据域，因此不能同时按字面满足这两项要求。
§3.2 的安装 state 校验也需要明确旧版没有 lifecycle state 时的来源接入规则。
本次不自行修改验收合同，不创建模拟 fixture、迁移回执或伪备份。

建议确认以下迁移语义后再继续实现：保留并比较旧版实际存在的身份、业务、历史、搜索、
指标与 Redis v1 插件事实；对旧版不存在的专用告警、安全审计、独立 Admin Frontend 和
lifecycle state，明确记录源端不存在，并在目标端通过正式迁移/初始化建立和验证。
新建的告警、审计和管理端事实不得记作从旧版保留而来的事实。若要求非空旧版告警/审计，
则必须提供能从锁定源码真实运行得到这些事实的生成路径，不能替换历史来源或回填目标表。
