# 实施记录

本目录用于保存 `dev/imple/` 下各阶段实施方案的实际开发记录。

实施记录应镜像对应方案的阶段目录和 Markdown 文件名，例如：

```text
dev/imple/Phase-00/Phase-00-01-工程骨架与基础设施.md
dev/logs/Phase-00/Phase-00-01-工程骨架与基础设施.md
```

日志记录实际交付、必要验证结论、计划偏差、已知限制和后续项，不得将未执行的计划写为已完成。
能从 diff 或 CI 定位的文件清单和完整输出不重复抄写；引用实际 CI run，或记录本地必要命令、
范围与结果。规则、规划和导航维护直接使用对应正文与提交说明，不另建阶段日志。

## 证据按用途留存

- 日常测试、构建和检查由既有入口与 CI 记录；重复成功输出和临时调试材料没有独有用途时可清理。
- 失败诊断在定位或接续仍需要时保留。私有原始材料放在本次归属的运行目录，按实施方案约定的期限和容量保存，不自动提交到本目录。
- 仍被容量、恢复、正确性或发布结论引用的证据，保留候选身份、环境与方法，以及足以复核结论的关键原始数据；失败结论适用同一要求。
  大型材料可放在可靠归档中，已有结论正文保存定位信息与校验摘要；长期依据不能只指向会过期的 CI artifact。

历史材料按根[默认清理与证据要求](../../AGENTS.md#架构与证据)处理；纯历史过程记录可由
可定位的 Git revision 保留。证据移出工作树前核对可访问性和身份，并更新当前引用。
不为清理新建证据台账、保留标签或占位页，不编辑原始回执、不换绑候选、不改写历史结论。
已分配验收合同中的材料、绑定与完成条件继续按其合同执行。
