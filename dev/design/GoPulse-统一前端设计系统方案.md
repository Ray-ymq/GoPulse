# GoPulse 统一前端设计系统方案

- 状态：提案
- 日期：2026-10-14
- 适用范围：`frontend` 用户端、`admin-frontend` 管理端、`frontend-shared` 共享层
- 目标：统一品牌体验，保留用户端和管理端的任务差异

## 1. 结论

GoPulse 使用一个统一的品牌设计系统，并提供两种布局变体：

1. 用户端使用内容优先的社区时间线。
2. 管理端使用状态优先的操作控制台。

两端共用颜色语义、字体、间距、图标、按钮和反馈规则。两端不强制使用相同的页面布局和信息密度。

这种方案可以保持品牌一致，也可以让不同用户快速完成各自的主要任务。

## 2. 设计目标

### 2.1 目标

- 让用户在首屏理解当前页面的主要任务。
- 让系统状态同时使用文字、图标和颜色表达。
- 让空数据、失败、权限不足和过期数据都有明确的下一步。
- 让用户端和管理端看起来属于同一个产品。
- 让设计规则可以通过共享令牌和组件复用。
- 让桌面端和移动端都可以完成主要任务。

### 2.2 非目标

- 不改变后端 API、数据合同和权限模型。
- 不把用户端改造成管理后台。
- 不把管理端改造成社交时间线。
- 不为了视觉统一而重写所有业务页面。
- 不在当前阶段引入新的 UI 框架。

## 3. 共同设计方向

共同气质为“浅色、克制、清晰、可长期使用”。

| 设计维度 | 统一规则 |
| --- | --- |
| 页面背景 | 冷色浅灰。用户端的内容区域可以使用白色连续画布。 |
| 内容表面 | 白色为主。卡片和列表使用细边框。默认不使用强阴影。 |
| 主色 | 使用统一品牌蓝。主色用于当前导航、主要操作和可交互链接。 |
| 语义色 | 绿色表示正常，琥珀色表示需要关注，红色表示失败或危险，蓝色表示处理中或信息。 |
| 图标 | 使用统一的线性图标。图标按钮必须提供可访问名称。 |
| 圆角 | 小控件使用小圆角，容器使用中等圆角。避免全页面使用胶囊形状。 |
| 阴影 | 只用于表达层级。列表行和用户帖子不默认使用浮夸阴影。 |
| 信息密度 | 管理端中等偏高。用户端以阅读舒适和内容连续性为优先。 |
| 动效 | 短时、低幅度。减少动效时不影响任务完成。 |

### 4.1 令牌使用规则

- 新增样式优先使用 `--gp-*` 令牌。
- 不为单个页面创建近似的蓝色、灰色或状态色。
- 后端状态值不直接决定视觉颜色。先映射为产品状态，再使用语义令牌。
- 组件不直接依赖 `--admin-*` 或 `--user-*` 私有令牌，除非该规则只属于对应布局。
- `frontend-shared/tokens.css` 作为共享令牌的唯一入口。

## 5. 两种布局变体

### 5.1 用户端：内容优先

用户端的主要任务是阅读、发布、搜索、互动和管理个人资料。

布局结构：

```text
┌──────────────┬─────────────────────────────┬──────────────┐
│ 轻量导航     │ 页面标题、筛选、内容时间线   │ 社区上下文   │
│ 首页         │ 发布框                       │ 系统状态     │
│ 搜索         │ 帖子                         │ 热门话题     │
│ 通知         │ 帖子                         │ 推荐用户     │
│ 收藏         │                              │              │
└──────────────┴─────────────────────────────┴──────────────┘
```

规则：

- 导航使用浅色背景和低对比度边框。
- 中央内容区是视觉重点。
- 帖子使用连续的内容行，不为每个帖子添加厚重卡片阴影。
- 帖子标题、正文、作者、时间和操作保持稳定顺序。
- 点赞、收藏、关注和分享必须显示当前状态。
- 右侧内容只提供上下文，不抢占主内容的注意力。
- 移动端使用底部导航，发布操作保持容易点击。

当前用户端的主要实施入口：

- `frontend/src/components/UserAppShell.vue`
- `frontend/src/user.css`
- `frontend/src/views/PostsView.vue`
- `frontend/src/views/SearchView.vue`
- `frontend/src/views/ProfileView.vue`

### 5.2 管理端：状态优先

管理端的主要任务是查看系统状态、查询数据、配置组件和处理异常。

布局结构：

```text
┌──────────────┬────────────────────────────────────┐
│ 深色分组导航 │ 顶部路径、用户入口和全局操作        │
│ 概览         ├────────────────────────────────────┤
│ 可观测       │ 页面标题、摘要、主要操作            │
│ 采集管理     │ 状态卡片、查询条件、表格、详情       │
│ 系统管理     │                                    │
└──────────────┴────────────────────────────────────┘
```

规则：

- 侧栏保持稳定，按用户任务分组。
- 页面标题说明当前任务，页面描述说明作用范围。
- 首屏先显示状态摘要，再显示查询、列表或详情。
- 详情优先显示决策所需信息，技术字段放到次级区域。
- 表格首列显示对象名称，操作列保持简洁。
- 多字段编辑使用抽屉或独立页面。
- 移动端将侧栏变为抽屉，表格允许横向滚动或转为列表。

当前管理端的主要实施入口：

- `admin-frontend/src/components/AdminLayout.vue`
- `admin-frontend/src/styles.css`
- `admin-frontend/src/components/AdminStat.vue`
- `admin-frontend/src/components/AdminTrend.vue`
- `admin-frontend/src/views/DashboardView.vue`
- `admin-frontend/src/views/ObservabilityLogsView.vue`
- `admin-frontend/src/views/AlertsView.vue`
- `admin-frontend/src/views/ObservabilityExportersView.vue`

## 6. 组件规范

### 6.1 应用壳层

共享能力：

- 品牌标识。
- 分组导航。
- 当前页面状态。
- 移动端导航切换。
- 跳转到主要内容的 Skip Link。
- 用户入口和退出反馈。

布局差异：

- `AdminLayout` 使用管理端侧栏和顶部路径。
- `UserAppShell` 使用用户端轻量导航和内容时间线。
- 两者共享图标、焦点、按钮和状态语义，不共享所有布局类名。

### 6.2 按钮

按钮只表达一个动作。

| 类型 | 用途 |
| --- | --- |
| 主按钮 | 创建、保存、发布、确认等当前区域的主要动作。 |
| 次按钮 | 刷新、查看、取消等低风险辅助动作。 |
| 文字按钮 | 查看全部、展开、返回等弱强调动作。 |
| 图标按钮 | 刷新、关闭、更多等空间受限动作。必须有可访问名称。 |
| 危险按钮 | 删除、停止、重置、覆盖等不可逆动作。 |

按钮处于进行中状态时：

- 禁止重复点击。
- 文案显示正在执行的动作。
- 失败后保留用户已经填写的内容。

### 6.3 状态徽标

状态徽标必须包含文字。颜色和圆点不能单独承担状态含义。

推荐的产品文案：

| 后端或内部状态 | 用户端文案 |
| --- | --- |
| `running` | 运行中 |
| `healthy` | 正常 |
| `starting` | 启动中 |
| `stopping` | 停止中 |
| `stopped` | 已停止 |
| `failed` | 操作失败 |
| `firing` | 触发中 |
| `recovered` | 已恢复 |
| `unknown` | 状态未知 |
| `stale` | 数据已过期 |

技术状态值可以在详情、日志和高级筛选中保留，但不应作为普通用户看到的唯一文案。

### 6.4 状态和反馈组件

建议扩展现有 `ProductState.vue`，形成共享状态组件：

- `ProductLoading`：正在加载，并说明正在读取什么。
- `ProductEmpty`：说明为空原因，并提供创建、搜索或刷新入口。
- `ProductNotice`：用于成功、信息和低风险提示。
- `ProductError`：保留错误上下文，并提供重试或修正方向。
- `ProductStatus`：统一状态文字、圆点和语义色。

状态最少支持以下流程：

```text
初始 → 加载中 → 成功
             ↘ 失败 → 可重试
```

另外支持：空数据、部分可用、数据过期、权限不足、未配置和并发修改。

### 6.5 表单

- 标签放在输入框上方。
- 相关字段按用户任务分组。
- 占位符只显示示例，不替代标签。
- 错误信息紧邻字段，并说明修正方法。
- Token、密码和密钥默认隐藏。
- 关闭有未保存内容的表单时提醒用户。
- 影响范围大的设置在保存前说明影响。

### 6.6 图标

- 统一使用线性图标。
- 图标笔画和视觉重量保持一致。
- 用户端导航不再使用 `⌂`、`⌕`、`♧` 等字符图标。
- 建议新增共享 `ProductIcon.vue`，由管理端和用户端共同使用。

## 7. 页面模板映射

| 业务页面 | 推荐模板 | 主要状态 |
| --- | --- | --- |
| 系统概览 | 摘要卡片 + 组件表格 + 趋势 + 最近事件 | 正常、部分不可用、数据过期 |
| Metrics | 查询条件 + 关键指标 + 趋势图 +采样表 | 加载、无采样、查询失败 |
| Logs | 精确筛选 + 日志表格 + 详情面板 | 加载、空结果、服务不可用、旧结果 |
| Events | 筛选 + 事件时间线或列表 | 加载、空记录、分页失败 |
| Alerts | 告警摘要 + 列表 + 详情 | 触发中、已恢复、已关闭、数据异常 |
| 告警规则 | 规则列表 + 抽屉编辑 | 未配置、保存失败、并发修改 |
| Exporter | 插件目录 + 状态详情 + 配置表单 | 未安装、运行中、失败、更新中 |
| 用户角色 | 精确查询 + 用户摘要 + 角色操作 | 输入无效、用户不存在、权限不足 |
| 管理审计 | 筛选 + 审计表格 + 分页 | 空记录、查询失败、游标失效 |
| 用户首页 | 发布框 + 内容时间线 + 社区上下文 | 加载、空时间线、刷新失败 |
| 搜索 | 搜索框 + 类型切换 + 结果列表 | 未输入、无结果、服务不可用 |
| 用户资料 | 资料摘要 + 编辑区 + 用户帖子 | 加载、保存失败、字段校验错误 |

## 8. 当前项目改造计划

### 阶段 1：共享基础层

目标：建立唯一的共享视觉基础。

任务：

1. 将 `frontend-shared/tokens.css` 改为完整的 `--gp-*` 令牌集合。
2. 将 `--admin-*` 和 `--user-*` 中可共享的值迁移到 `--gp-*`。
3. 新增共享图标组件或共享图标路径集合。
4. 统一焦点环、按钮高度、禁用态和减少动效规则。

交付物：共享令牌、共享图标、共享基础按钮规则。

### 阶段 2：状态与反馈组件

目标：让两端的加载、空数据和失败反馈使用同一套规则。

任务：

1. 扩展 `ProductState.vue` 的文案和操作插槽。
2. 新增 `ProductStatus.vue`。
3. 新增可复用的空状态和错误状态模板。
4. 为状态组件补充键盘和屏幕阅读器测试。

交付物：统一状态组件和状态文案映射。

### 阶段 3：管理端迁移

目标：保留当前管理端信息架构，统一视觉和交互细节。

任务：

1. 合并 `admin-frontend/src/styles.css` 中重复的壳层定义。
2. 将硬编码颜色替换为共享令牌。
3. 将 `AuditView.vue`、`UsersView.vue` 的简单状态提示升级为统一状态组件。
4. 将告警规则内嵌表单迁移到抽屉或独立编辑区。
5. 将 `running`、`firing`、`failed` 等状态映射为产品文案。
6. 检查所有危险操作的确认、失败保留输入和重试路径。

交付物：管理端页面实现与样例设计保持一致。

### 阶段 4：用户端迁移

目标：保留内容时间线的轻量感，同时与管理端形成品牌一致性。

任务：

1. 保留用户端的内容流布局和移动底部导航。
2. 将导航字符图标替换为共享线性图标。
3. 将用户端颜色和焦点规则迁移到共享令牌。
4. 统一发布、点赞、收藏、关注和删除反馈。
5. 为搜索、通知、收藏和资料页补齐空数据方向。
6. 保持帖子列表的低阴影和连续阅读体验。

交付物：用户端页面与管理端共享品牌基础，但保留内容产品布局。

### 阶段 5：视觉和交互验收

目标：确认设计在主要分辨率、状态和交互路径中可用。

任务：

1. 检查桌面端 1440px、1024px 和移动端 390px。
2. 检查加载、成功、空数据、失败、权限不足和数据过期状态。
3. 检查键盘导航、焦点、Escape 关闭和屏幕阅读器名称。
4. 检查颜色对比度和减少动效模式。
5. 对比 HTML 样例和 Vue 页面，确认间距、颜色和层级一致。

## 10. 验收标准

### 10.1 视觉一致性

- 两端使用同一品牌蓝和语义色。
- 两端使用同一图标风格。
- 两端的按钮、焦点和禁用态行为一致。
- 管理端使用卡片和数据密度，用户端使用时间线和阅读密度。
- 页面不出现无来源的近似颜色和重复令牌。

### 10.2 交互完整性

- 所有异步操作都能表达加载、成功和失败。
- 空数据状态说明原因，并提供下一步。
- 错误信息说明原因或处理方式。
- 删除、停止、覆盖和角色变更都有明确确认。
- 操作失败时保留用户输入。
- 进行中的按钮不能重复提交。

### 10.3 可访问性

- 颜色不是唯一的状态表达方式。
- 图标按钮有 `aria-label` 或可见文本。
- 表单标签和错误信息正确关联。
- 键盘可以访问主要操作和关闭控件。
- 焦点状态清晰可见。
- `prefers-reduced-motion` 不影响任务完成。

### 10.4 响应式

- 390px 宽度下用户端可以阅读、发布、切换导航和执行主要操作。
- 390px 宽度下管理端可以打开导航、查看状态和提交主要表单。
- 表格无法压缩时允许横向滚动。
- 页面标题、主要操作和状态信息在移动端不丢失。

## 12. 变更边界

本方案只约束前端视觉、布局、状态和交互表达。以下内容不在本方案范围内：

- API 字段和接口路径。
- 后端状态机和事件合同。
- 权限判断逻辑。
- 数据查询窗口和分页策略。
- 生产部署和构建流程。

如果后端状态或权限语义发生变化，前端需要更新状态文案映射和错误处理，但不应新增一套视觉规则。
