## 决策与基线变更

在既定目标内细化接口、数据结构、尚未赋值的参数和迁移步骤，可在对应详细设计或正式方案记录决策依据。实现必须遵守适用的架构约束、硬依赖和仓库规则；不能把细化解释为改变目标的授权。

发现目标冲突、设计假设经验证不可行或需要调整项目范围、终点、所有权、共同契约及正确性要求时：

1. 停止受影响的工作，保留实际证据和执行停点。
2. 在评审材料中记录原文位置、问题与证据、拟调整方案、两份设计及大纲的一致性影响、已分配合同和证据的影响，并在本页登记链接。
3. 提交用户评审。未经用户明确批准，提案保持草案，不能由下级文档、索引或实施代码覆盖生效目标。
4. 获批后以新文件建立替代基线，核对两份设计及大纲；未变更部分可以引用冻结原文。登记生效日期、批准记录、文件入口及被替代范围，永久保留旧文件的原路径和原文。
5. 若影响已分配实施合同，另行明确修订范围、门禁和进入条件。新基线本身不授权产品执行，不重写历史日志、候选回执或证据，也不预留未来编号。

既有实施方案的批次解锁和完成规则继续适用；不能因新基线获批就跳过预算、分支、固定门禁或完成提交。
