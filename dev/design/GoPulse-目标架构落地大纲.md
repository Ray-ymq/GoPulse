## 0. 文档职责与使用方式

架构依据为[高并发架构设计](<../../docs/GoPulse 高并发架构设计.md>)和[可观测架构设计](<../../docs/GoPulse 可观测架构设计.md>)。前者负责业务、一致性和容量，后者负责观测、实验以及共同身份和环境资源合同。本文沿这些目标向下组织工作，不建立新的目标架构。

落地过程为：**目标能力 → 共同合同 → 模块详细设计 → 跨模块协作 → 部署与迁移 → 系统验收 → 正式实施批次**。

| 材料 | 负责的内容 |
| --- | --- |
| 两份架构设计 | 项目定位、目标边界、模块责任、共同合同和设计终点 |
| 本大纲及后续 `dev/design/` 专题 | 目标与现状的差距、详细设计目录、接口与状态、依赖、迁移和验收方向 |
| `dev/contracts/` | 注明适用版本和实际实现范围的技术合同；目标草案不能冒充已实现合同 |
| Phase 总实施方案与分方案 | 正式批次、版本、分支、允许文件、固定门禁、预算和完成条件 |
| 实施日志与能力状态 | 实际修改、执行结果、证据、已知边界和未完成项 |

当前阶段状态按 [Phase 20 总实施方案](../imple/Phase-20/Phase-20-总实施方案.md)：2026-10-05 按用户要求仅保留已完成的 01～04，在 `2.2.4` 结束；原 05、06 已取消并移除实施文件。资源预算与最终持续运行未交付，历史失败和证据保留。后续设计以 `2.2.4` 为基线，不再以原 05/06 完成为前置条件；新增执行范围须由新总实施方案分配。

下文 C、R、V、A 编号仅用于专题和场景引用，不是 Phase、版本、分支或已分配批次。阅读和编写从上到下展开；实际实施顺序由依赖和正式合同决定。

## 1. 目标能力与现状差距

### 1.1 项目终点

| 目标能力 | 用户或使用者得到的结果 | 成立依据 |
| --- | --- | --- |
| 业务正确性 | 创建重试、重复投递、相反操作、编辑与删除竞态有明确结果 | 权威事实、命令结果、适用副作用完成依据和竞态案例 |
| 有界并发与恢复 | 热点、依赖故障、后台积压时资源与拒绝行为可解释 | 指定负载下的分类 goodput、尾延迟、资源占用和恢复范围 |
| 多目标观测 | 同类目标、服务副本可以独立管理和查询 | 配置、执行、目标身份全链路保留及正确聚合 |
| 查询与诊断 | 可查历史窗口和业务阶段，区分事实、遥测、推断与未知 | 受限查询、持久状态查证、读取时间和证据引用 |
| 实验复现 | 他人可按相同条件重跑案例并复核结果 | 冻结候选、环境合同、配方、原始数据、校验和归属清理 |

这些能力共同构成两份设计的终点。完整 CMDB、多租户、任意协议接入、通用 DAG、自动根因判定、自研存储引擎不进入默认建设范围。统计分桶、收件箱信息流、读副本、分片、领域微服务、长连接和多地域扩展沿用业务设计中的触发条件。

## 2. 共同合同详细设计

本章对应可观测设计第 5 节及业务设计的完成、恢复和容量语义。共同字段以可观测设计为定义来源，业务专题引用同一含义。

### C1. 身份、权限与领域所有权

- 目录：账号、凭据和角色的 B2 接口；M9 的认证与领域授权适配；业务与平台装配；角色变更入口；凭证引用；审计归属。
- 产物：接口与调用方表、权限矩阵、私有字段边界、共享依赖及连接预算说明。
- 验收依据：管理角色事实不可取得时拒绝操作；资料投影不泄露私有字段；接口和执行边界都进行适用授权。

### C2. 对象、命令与关联身份

- 目录：应用/服务/运行实例；目标/插件版本/采集配置/采集执行；`data_epoch`、`experiment_id`、`command_id`、`event_id`、`object_id`、适用的 `object_version`、`consumer_id`、`projection_generation`、请求和 Trace 身份。
- 产物：字段字典、生成者与校验者、稳定性与作用域、必填/适用条件、存储与传播矩阵、历史数据兼容方式。
- 验收依据：重试保持命令身份，重投保持事件身份；服务实例和采集执行不混淆；旧数据代际不能覆盖恢复后的事实；索引重建仅改变适用投影代际。
- 成本边界：逐请求、命令、事件、对象、实验及 Trace ID 不进入普通指标标签；目标和实例集合有受控上限。

### C3. 完成、查证与失败语义

- 目录：事实提交、Broker 发布确认、消费者应用完成；入口接收、落库、查询可见；提交未知；适用副作用与无需副作用的结果；失败尝试和后续成功。
- 产物：阶段证据表、持久记录及其唯一范围、状态转换、公开结果和错误分类、跨存储非原子窗口说明。
- 验收依据：响应丢失可用同一命令查证；已发布不能代替全部副作用完成；搜索写入与当前查询可见分别核实；证据缺失保留未知。
- 数据边界：跟踪实际承诺的业务副作用；高频观测记录不因此新增逐条全局状态表。
- 业务与遥测边界：遥测不持有业务事务；遥测接收、落库或查询成功不作为普通业务事务提交或业务消息确认的前置条件。遥测缓冲、重试和丢弃按各信号合同有界执行。

### C4. 时间、统计与质量状态

- 目录：发生、采集、处理、落库和读取时间；时钟前提与误差；原始样本、展示采样与插值；counter/gauge/histogram；局部值和共享值；零、缺失、陈旧、部分结果与错误。
- 产物：时间字段和统计口径、聚合规则、质量状态及 API 表达、展示与告警使用规则。
- 验收依据：已知增量与实例重启的结果可重算；重复观测共享状态不能直接累加；查询失败不能生成恢复结论。

### C5. 期望配置、生效状态与有效快照

- 目录：配置身份、期望修订、观察修订、插件实际版本、候选准备/验证/提交/恢复、来源策略就绪、快照版本及有效性、凭证交付。
- 产物：跨模块激活时序、状态归属、旧回报处理、快照失效策略和恢复流程。
- 验收依据：M2 保存成功与 M3 生效分别展示；M4 策略就绪后才激活来源；旧修订不能覆盖新状态；控制端不可用时仅按有效授权快照继续运行。

### C6. 环境资源与故障隔离

- 目录：候选/配置/资源修订；角色实例数和发布重叠；CPU、内存、磁盘、连接、并发、在途和写入预算；采集、查询、诊断、评估及实验工具份额；恢复预留；实际生效核对。
- 产物：机器可读环境合同设计、模块申报与执行责任、物理共享关系、校验规则、超限行为及合同变更流程。
- 约束：访问同一物理数据库的全部角色满足业务设计的 `Σ(N_r × P_r) + C_reserve ≤ C_safe`，预留只计一次；安全容量须由指定环境验证。不同 schema、连接池或进程不构成后端故障隔离证明。
- 验收依据：扩容、发布、平台查询和维护共同运行仍遵守总量；声明与实际配置不一致时不能产出该合同下的容量结论。

### C7. 保留、清理、重放与恢复

- 目录：命令结果、事实事件、路由修订、必要完成记录、通知、统计去重、删除标记、构建会话和各类观测数据的留存；清理前置条件；备份和恢复代际。
- 产物：每类数据的所有者、保留目的、窗口、清理屏障、恢复来源、失败升级和成本表。
- 验收依据：必要副作用完成前不因已发布而清除事实事件；删除屏障覆盖可能旧写入；恢复同步核对事实、执行依据、缓存与索引；历史通知恢复能力单独说明。

### C8. 版本、错误与上线兼容

- 目录：接口/事件/数据/配置版本；新旧运行单元兼容；未知模式处置；暂时失败、永久数据拒绝、权限失败和证据缺口；特性启用和回退限制。
- 产物：兼容矩阵、上线顺序、回退条件及受影响验收集合。
- 验收依据：必要但暂不支持的事件可持久停放和诊断；普通存储不可用不能当作永久数据拒绝；已产生新生命周期数据后不回退到忽略其状态的读取版本。

## 3. 运行单元与装配详细设计

本章对应业务设计第 3、13 节和可观测设计第 6 节。保留模块化前台与既有异步进程基础，按具体职责和资源边界装配。

| 专题 | 详细设计目录 | 产物与验收依据 |
| --- | --- | --- |
| R1 业务入口与平台入口 | `business-api`、`platform-api` 的模块装配、路由、身份复用、配置、就绪、依赖降级和关停 | 运行模式及依赖表；真实独立启动、准入与排空；共享身份依赖诚实记录 |
| R2 独立投递与消费 | dispatcher 的领取/发布/排空；通知、搜索和正式采用后的统计消费；队列、prefetch、并发、期限 | API 扩容不自动增加 dispatcher；发布与消费各有预算；确认丢失和重启符合 C3 |
| R3 维护与恢复 | 按需重建、校准、物理回收、Outbox 清理、迁移及恢复；所有权、限速、暂停和接续 | 有限任务状态与停止规则；在线容量不足时让出资源；清理仅操作自有资源 |
| R4 平台数据面与后端 | Monitor/exporters、Router、Marshaller、OTLP 接收端及信号后端；通道、身份与预算 | 各运行单元配置与生命周期；业务 ES 与观测 ES 默认独立；共享宿主故障域记录在 C6 |

前台领域默认同进程；控制、查询和告警先在平台入口内明确逻辑边界和执行预算。额外拆进程须有具体隔离依据。统计 worker 仅在正式采用统计投影时装配，维护按需执行。

每次运行边界变化都要列出受影响源码、镜像、配置、启动/就绪/排空行为、迁移和回归。仅调整健康检查不代表角色装配已经完成。

## 4. 业务系统详细设计目录：M1 / B1～B10

下列“依赖”指专题所需的接口、合同或行为，不要求对应模块整体先完成。双向协作先共同确定合同，再按第 6 章的最小案例拆分交付；正式总方案将其转换为可执行的批次依赖。

### B1. 接入与流量准入

- 展开：请求形状与大小；认证、读取、写入、搜索、管理成本分类；身份/来源配额；类别与实例名额；期限传播；有界等待；热点跟踪；探针和排空名额；单层重试。
- 产物：请求类别与资源表、准入状态图、HTTP 结果、静态配额分配、指标及超限案例。
- 验收：配额超限与容量不足分别表达；超期工作不继续进入依赖；一类或一个热点饱和时保留约定余量。
- 依赖：C1、C4、C6、R1、B9；允许最大实例数与发布重叠先确定。

### B2. 身份、用户与关注关系

- 展开：B2/M9 接口；角色事实读取；密码计算预算；公开资料批量接口；关系唯一键；建立/取消顺序；用户生命周期竞态；关注流使用的关系查询。
- 产物：领域接口、权限与字段矩阵、关系事务和锁顺序、查询索引及兼容规则。
- 验收：关系重试不重复；相反操作的结果可解释；管理权限不可取得时拒绝；公开投影不带凭据或私有权限状态。
- 依赖：C1～C3、B9；关系串行范围的变化由竞态结果支持。

### B3. 内容、评论与删除生命周期

- 展开：创建幂等键与摘要；命令结果同事务；提交未知查证；内容单调版本与编辑冲突；父状态保护；逻辑删除；正文和关联数据物理回收；最小删除标记；通知及索引兼容。
- 产物：命令与内容状态图、事务/唯一约束、锁顺序、删除上线和回退条件、物理清理与留存合同。
- 验收：同键同请求得到同一结果，同键不同请求冲突；编辑/删除竞态不丢版本；删除后开始的新读和交互统一遮蔽；清理不生成重复业务事件。
- 依赖：C2～C3、C7～C8、B6、B7、B9；所有读取和消费者先理解删除状态，再启用新生命周期。

### B4. 点赞、收藏与热门对象

- 展开：用户/对象关系唯一性；目标状态命令与相反操作顺序；短事务父状态保护；完整建立/取消事件；自互动；收藏私有性；热点名额与锁等待。
- 产物：关系转换、事件覆盖、锁顺序、公开重试合同及代表性热点案例。
- 验收：不同用户交互不默认串行于父排他锁；重复操作无额外关系/计数/通知；删除后不新增关系；热点等待有界。
- 依赖：C2～C3、B1、B3、B6、B9；共享父锁必须验证编辑、删除、死锁和失败处置。

### B5. 页面、缓存、统计与信息流

- 展开：权威可见性与版本；版本正文缓存；公开作者；独立展示统计；个人关系批量读；同键合并及等待上限；回源预算；游标、候选扫描、补页轮次；稀疏关注流。
- 产物：页面数据与一致性表、批量接口、缓存键和迁移、查询成本、新鲜度与陈旧表现；采用统计投影时补初始基线、原子去重/计数与事实校准。
- 验收：个人状态不串用；旧回填不覆盖新正文；热门互动不反复失效未变正文；冷缓存和 Redis 故障只在预算内回源；页面工作量可数、可限。
- 依赖：C3～C4、C7～C8、B1～B4、B6、B9；完整转换流、基线和校准成立后才切换统计来源。

### B6. 可靠事件、应用完成与重放

- 展开：事实事件与通知策略；事件模式/路由修订；Outbox 租约、条件更新和发布确认；独立队列；处理并发与 prefetch；退避和失败停放；必要副作用完成依据；留存、积压水位和重放预算。
- 产物：事件覆盖表、适用消费者集合、领取/发布/应用时序、完成记录与事务边界、持久空间准入、恢复和只读状态契约。
- 验收：网络发布前结束领取事务；租约丢失不能伪造完成；发布和消费确认丢失允许重投；副作用幂等；不能借旧投影代际的完成证明新代际完成。
- 依赖：C2～C3、C6～C8、R2、B9；消费者领域模块共同确定完成含义和无需副作用的结果。

### B7. 搜索投影、删除屏障与在线重建

- 展开：候选查询及事实过滤；对象规范投影、版本冲突语义和持久删除投影；数据库工作与 ES I/O 分离；构建会话；扫描前绑定持久队列；并发变更与迟提交；追赶、切换意图、实际 alias 查证、退役与游标失效。
- 产物：版本/删除竞态表、无跨系统持锁时序、构建状态与所有权、覆盖证明、追赶和切换条件、崩溃恢复与受限可见性接口。
- 验收：旧消息、旧扫描不覆盖更高删除版本；同版本投影确定；队列排空包含未确认与正在写入工作；切换恢复核对真实 alias；最终事实无遗漏、无复活。
- 依赖：C2～C3、C6～C8、R3、B3、B6、B9；内容版本、规范投影和持久删除屏障通过验证后，才移除 ES 写入期间的数据库持锁。
- 重建迁移门槛：新捕获、追赶和切换恢复机制实现并通过竞态验证前，保留现有重建/删除协调保护；移除 ES I/O 期间的数据库持锁不代表可以移除这类保护。不能用 `MAX(outbox.id)` 充当提交水位。

### B8. 通知与个人消息状态

- 展开：完整事实事件、接收人策略、无需通知结果；事件唯一范围；通知与完成依据同事务；列表索引、已读授权、删除引用遮蔽、历史恢复；未读派生值按需求单独定约。
- 产物：通知处理时序、持久数据与完成关系、读取和已读接口、删除后的展示形状与恢复边界。
- 验收：重复投递只有一个适用结果；用户不能操作他人通知；删除前后到达的事件不暴露正文；消费积压时在线读取有保留资源。
- 依赖：C1～C3、C7、B3、B6、B9；最新关系状态不能代替历史通知事实。

### B9. 数据访问、持久化与恢复

- 展开：领域 Repository 所有权；共享总连接、事务期限、锁顺序与死锁处置；各列表索引与扫描成本；执行依据增长；备份覆盖；恢复到过去的数据点、新数据代际、派生存储重建和旧消息拒绝。
- 产物：数据所有权/索引/留存矩阵、连接与事务预算、代表性查询计划、迁移和恢复准入流程。
- 验收：发布及恢复期间连接总量成立；事实与必要执行依据共同恢复；缓存/索引丢失可按合同重建；删除状态在恢复中仍受保护。
- 依赖：C2、C6～C8、M8；各领域申报实际路径和数据约束。权威事实不可用时不能以未经校验的缓存正文替代当前可见性。

### B10. 容量、发布、排空与诊断接口

- 展开：分类延迟/期限/拒绝合同；异步新鲜度和恢复；准入、连接、消费、维护份额；新旧版本兼容；角色排空；提交未知处理；按身份和代际限定的只读业务阶段查询。
- 产物：业务容量参数、预算与生效修订、发布/维护流程、只读状态 API 的权限/对象数/时间/连接/期限和缺口表达。
- 验收：状态返回各记录及读取时间，保留跨存储非原子边界；维护不占尽前台预算；诊断不直接任意扫描业务表；普通请求按有效配置运行，不同步调用 M8。
- 依赖：C1～C8、R1～R3、B1～B9、M8；B10 提供并执行业务份额，M8 汇总环境合同。

- 展开：字段到存储的映射；批量/并发/in-flight；稳定重试身份；暂时失败与永久数据拒绝；连续完成位置和归属 fencing；不同后端隔离；索引归属、迟到、清理及恢复。

- 验收：较晚成功不越过未完成记录；旧消费归属不能提交；普通后端故障不永久丢弃；一个后端的阻塞范围明确；重投身份不变。

### M6. 历史查询、统计解释与关联

- 展开：授权对象、实例、代际和历史窗口；指标目录；各信号适配器；时间跨度、时序数、点数、扫描和期限；新鲜度/采样/缺失/部分结果；业务持久状态与指定索引代际的可见性查询。
- 产物：公共查询与质量 schema、适配器合同、统计口径、成本拒绝行为、历史查询和关联页面。
- 验收：同类目标和服务副本可分别选择；速率、错误比例和分位数可解释；无数据、真实零及查询错误分开；持久事实与遥测各带来源、版本和读取时间。
- 依赖：C1～C4、C6～C8、M2、M5、B10；不得直接扫描业务表或开放无界跨存储查询。

### M7. 持久告警与业务阶段诊断

- 展开：规则修订、评估周期/预算/归属；触发、持续、恢复、未知和陈旧；状态持久化及证据引用；按命令/事件/对象组织业务阶段；已知、推断和缺口；查询可见与写入完成分别查证。
- 产物：告警状态机、旧评估 fencing、查询口径、诊断判断依据表和告警/阶段页面。

- 依赖：C1～C4、C6、C8 和 M6 的一致查询解释支撑告警评估；业务阶段诊断另依赖 B10 的持久状态及适用的受限可见性查询，不能将其设为所有告警的前置条件。

### M9. 公共能力装配

按 C1～C4、C8 提供领域接口适配、共同身份、错误/时间及有界日志、Tracing、组件指标能力。业务与平台分别装配，账号/角色仍由 B2 唯一维护。公共库不持有其他模块的状态或跨所有者写权限。

遥测故障场景须在业务依赖可用、配置与资源预算有效的条件下，分别核验事实提交、业务响应、消费者副作用及确认、遥测缓冲/重试/丢弃和证据缺口。观测接入、缓冲、存储或 OTLP 出口阻塞和不可用时，普通业务提交与按处理/重试合同进行的消息确认不等待遥测成功；仅展示遥测缺失不能算通过。

产物为跨模块时序、字段传播/持久证据表、权限与预算、迁移和失败案例。复用已完成单链路传播与新鲜度基础，新增持久查证能力按新合同验收。

3. 信号经 M4/M5 保持目标与实例身份；M6 分别查询，M7 使用同一质量解释。
4. 场景覆盖单目标故障、单配置更新、失败恢复、旧回报、控制端不可用及执行端重启。

产物为最小对象关系、激活/恢复时序、端到端身份和管理流程。历史默认目标明确标注，不能伪造采集当时不存在的身份。

产物为竞态交错表、最终事实与投影校验、锁/预算、删除及索引切换证据。证明热点正确性和恢复边界，统计分桶等条件扩展由具体证据另行解锁。

### 6.1 上线与迁移顺序

| 变化 | 启用前条件 | 回退及清理边界 |
| --- | --- | --- |
| 进程分离 | 入口、身份、配置、就绪、排空及共享预算通过 | 新旧角色共同遵守租约/owner 和连接总量；允许重投，但不丢事件或产生重复业务副作用 |
| 命令/事件/完成依据 | 新结构迁移、消费者模式兼容、历史与新记录范围明确 | 必要未知事件保留；不伪造历史幂等结果或完成记录 |
| 删除生命周期 | 所有读取、交互、通知和索引理解删除；持久屏障有效 | 已存在新状态时禁止退回忽略状态的读取版本 |
| 分层缓存和统计 | 键空间隔离、完整事实转换、初始基线和校准成立 | 不混用个人字段或不同统计合同；保留预算内回源 |
| ES I/O 期间数据库持锁移除 | 内容版本、规范投影及持久删除屏障通过验证 | 不因此移除现有重建/删除协调保护 |
| 重建/删除协调保护移除 | 新捕获、追赶和切换恢复机制实现并通过竞态验证 | 未通过时继续保留现有协调保护；旧写入失效条件仍须核验 |
| 索引代际切换 | 捕获、扫描、追赶、删除校验及切换恢复通过 | 未核实实际 alias 和旧写入失效前不回收索引/标记 |
| 多目标采集 | 模型迁移、来源策略、执行恢复和查询身份贯通 | 配置、实际版本和历史身份分别表达 |
| 恢复到过去数据点 | 新代际持久化、事实/执行依据/派生存储核对通过 | 旧事件拒绝；重放按恢复合同生成依据，不只改标签 |

迁移流程在详细设计中展开为新增兼容结构、部署兼容读取/消费者、迁移或构建、验证、启用、受限退役。每一步确定失败停点、允许回退和证据要求。

## 7. M8：实验、环境与执行成本

### 7.1 最小环境基础

- 候选与输入：代码 revision、制品/Bundle/manifest、工具/config/profile/依赖 digest、数据代际、实验身份和实际生效修订。
- 资源与负载：C6 汇总、压测器与采样器预算、数据规模、操作比例、热点、请求体/页大小、缓存状态、到达模型和依赖部署。
- 所有权：项目、容器、网络、卷、进程和证据路径；故障/恢复/清理均只作用于自有资源。
- 执行记录：计划槽位、实际发出、工具丢弃、准入、拒绝、终态、业务成功、各维度水位与恢复时刻；实际成本、停止和缺失项。

产物为环境合同、实验定义、原始证据 schema、累计成本台账与验证入口设计。先复用现有 lifecycle/loadtest/验收工具，再针对具体缺口扩展；普通请求和信号处理不逐次调用 M8。

### 7.2 实验编排与结果

详细设计依次展开：冻结输入 → 确定性预检 → 基线 → 有界故障 → 业务/观测独立观察 → 恢复 → 校验 → 原始证据及脱敏发布 → 归属清理。各阶段均可形成失败或暂停结果，不把后续计划步骤预填完成。

goodput 仅计符合业务语义及相应时间合同的工作；成功、拒绝、失败分别报告延迟。业务正确性检查与遥测检查独立，Trace 数量不能证明事实正确。诊断区分观察到的失败、已证明原因和相关现象。

### 7.3 成本、失败与接续

遵守[仓库规则](../../AGENTS.md)和[执行预算规则](../rules/implementation-execution-budget.md)。产品开发、验收工具开发和必要长时正式实验分开核算；普通实施文件目标 120 分钟、累计上限 180 分钟，超出前拆分未开工范围。

分方案必须登记发现/实现、直接检查、构建/环境、真实验收、诊断、发布/清理预算；实验按单元数乘以预热/测量/恢复，加启动、配方和清理成本计算。长时实验另列不可压缩窗口与有限总上限。

50%/80% 报告和下一命令前预算检查按根规则执行。首个验收基础设施失败停止全矩阵，最小边界复现；同一未解决原因至多两次有界诊断，每次默认至多 10 分钟。预算耗尽或诊断停点保存进展并有界收尾，明确恢复指令及修订剩余计划后才能继续。

候选和工具变更不重置成本。列出受影响门禁及仍有效的检查；不更改原回执身份，不把旧候选证据换绑。恢复粒度按工具实际支持登记，不承诺尚未实现的 resume。用户暂停保留有效证据和停点，规划修订不触发恢复。

| A12 实验失败或停止 | M8 及被操作模块 | 已执行/失败/未开始清单、原始证据、有界恢复/清理与真实接续能力 |

各正式案例具备 case_id、前置身份、操作、预期、期限/阈值、证据路径、失败分类及归属清理。成功基础检查在相关输入不变时保持有效；只有具体变更或回归风险才扩展检查。静态/单元检查与真实依赖验收各承担其有效范围。

结果分别登记：实现是否完成、验收执行是否完整、能力阈值是否达到。工具故障、漂移、缺证据或不安全清理不能产生能力结论；完整执行发现容量边界不能冒充目标达标，确定性正确性/权限/数据安全门禁仍须通过。发布时严格核验实际选定的脱敏工件及来源。

必须在专题和正式方案中显式保留的硬依赖：

- 完整事实转换流 → 初始统计基线、原子去重/计数与校准 → 切换统计读取。
- 全部读取/交互/通知/索引兼容删除状态及持久屏障 → 启用删除生命周期 → 满足旧写入失效条件后清理屏障。
- 内容版本、规范投影和持久删除屏障通过验证 → 移除 ES I/O 期间的数据库持锁。
- 新捕获、追赶和切换恢复机制实现并通过竞态验证 → 允许移除现有重建/删除协调保护；新索引正式使用仍须满足内容、版本、删除及切换校验。
- 目标/配置/执行身份 → 来源策略就绪 → 实际执行生效 → 存储身份保持 → 对象查询和正确聚合。
- M6 查询语义与质量 → 告警评估。
- M6 查询语义与质量 + 持久业务阶段及适用的受限可见性 → 业务阶段诊断。
- 各模块预算及实际生效 → 环境总量冻结 → 正式容量/故障/恢复结论。

专题可在不依赖未定结果的范围内独立细化。每个专题的具体实施顺序、前一批集成结果和解锁证据由正式总方案确定。
