# Phase 3：Elasticsearch与业务搜索

> 本文档是阶段开发提纲，具体接口、数据模型、消息格式和部署参数将在本阶段进入详细设计时补充。

## 版本规划

- 版本线：`0.4.x`；阶段基线：`0.4.0`。
- 执行批次从 `0.4.1` 起编号，具体目标版本和开发分支由 Phase 3 总实施方案统一分配。
- 本阶段全部完成并通过里程碑验收后，发布可用业务系统版本 `1.0.0`。

## 阶段目标

让 Elasticsearch 首先服务真实业务搜索，提供帖子标题与正文的全文检索能力。

本阶段完成后，应形成可独立运行和验证的结果，并能够直接支撑 Phase 4。

## 里程碑定位与 MVP 贡献

- 所属里程碑：Milestone 1，业务系统 MVP。
- 本阶段为该里程碑的收尾阶段，以可重建的全文搜索补齐内容发现能力；Phase 3 验收通过后，业务系统 MVP 完成并发布 `1.0.0`。
- `开发范围`和`验收标准`中的内容是本次 MVP 的必需能力；复杂推荐、排序和分析等能力按`本阶段不做`明确延后。

## 开发范围

- 帖子搜索索引。
- 索引建立与重建流程。
- Backend 统一搜索入口。
- 前端帖子搜索交互。

## 核心任务

- 将 MySQL 中的帖子数据同步或异步建立为搜索索引。
- 实现标题与正文关键词搜索。
- 通过 Backend 代理所有 Elasticsearch 查询。
- 提供从 MySQL 重建搜索索引的能力。

## 前置依赖

- Phase 2 业务异步化完成。
- 帖子数据已由 MySQL 持久化。
- Elasticsearch 可用。

## 阶段产物

- 帖子全文搜索能力。
- 搜索索引写入链路。
- 索引重建流程。
- 搜索页面或入口。

## 最小端到端闭环

`MySQL 帖子事实 → 搜索索引写入或重建 → Backend 搜索入口 → Frontend 展示搜索结果`

该闭环必须同时证明正常索引、关键词查询和从 MySQL 重建索引可用，不能只交付 Elasticsearch 连接或孤立的索引写入能力。

## 验收标准

- 可按关键词搜索帖子标题或正文。
- 前端不直接连接 Elasticsearch。
- 删除搜索索引后可由 MySQL 恢复。
- MySQL 仍为业务事实来源，Elasticsearch 仅作为搜索索引。

## 阶段完成与停止条件

- 最小端到端闭环及全部阶段验收标准通过，且 Milestone 1 的业务能力可共同运行。
- 对应实施记录已如实记录改动、验证、偏差和后续事项，固定完成门槛通过且无 P0/P1 阻塞。
- 达到上述条件后完成 `1.0.0` 里程碑验收并停止扩展；非阻塞搜索增强转入后续事项，阶段产物作为 Phase 4 的输入。

## 本阶段不做

- 将 Elasticsearch 作为业务事实来源。
- 日志与事件存储链路。
- 复杂搜索推荐、排序和分析能力。

## 总实施方案生成与批次切分约束

- 默认规划 1～2 个实现批次，再固定保留 1 个 Review、集成验收与阶段收口批次，总计尽量控制在 2～3 个批次。
- 超过 3 个批次时，总实施方案必须记录具体的风险隔离、依赖关系或独立交付理由。
- 实现批次按可运行、可验证的搜索闭环切分，不按索引、Backend、Frontend 和测试等技术层机械拆分。
- 测试、文档和实施记录随对应能力完成；收口批次只执行跨批集成、固定验收和实际 Review 整改，不加入新的功能范围。
- API、索引结构、同步机制和部署参数由总实施方案根据实施前的真实代码基线确定，阶段提纲不提前冻结。
