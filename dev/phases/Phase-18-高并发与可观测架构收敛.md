# Phase 18：高并发与可观测架构收敛

## 阶段目的

在 Linux `amd64` Compose 环境中，先记录单副本容量边界，再完成计算层多副本、业务与观测
故障域隔离、显式背压和独立诊断。Phase 18 以完整事实为验收结果，不要求所有目标达到阈值。

## 已完成部分

- Phase-18-01 已交付 `2.0.1` 数据/负载工具与失败基线，不能证明稳定承载 `150 RPS`。
- Phase-18-02 已交付 `2.0.2` Outbox 满批连续 claim 修复，容量结论保持 `boundary_found`。
- 上述历史证据保持原貌，不重放、不补造，也不计入新批次的两次验收。

执行两轮，不能修改现有回执或追加第三轮。

## 验收语义

每个最终验收单元只能执行两次：首次一次、相同条件重复一次。数值指标保留两次原值并取算术
平均；确定性检查记录 `0/2`、`1/2` 或 `2/2`。不允许第三次运行或选择性保留较好结果。

以下结果都算完成固定验收并更新批次版本：

- `target_met`：目标达到；
- `boundary_found`：目标未达到或发现产品边界；
- `execution_failed`：命令或验收基础设施失败，但失败阶段、退出码与输出证据完整。

版本完成不等于能力通过。没有完成两次、证据丢失、候选无法识别或修改了文件清单外内容，属于
流程未完成，不能伪装为测试失败。

## 阶段边界

- Monitor 继续保持单实例和插件生命周期唯一所有者。
- MySQL、Redis、RabbitMQ、Kafka、VictoriaMetrics 和两个 Elasticsearch 仍可为单节点；
  本阶段不声明状态层 HA。
- 不新增业务功能、外部告警、生产安全协议或 Kubernetes 资源。
- 完成 Phase-18-05 后停止，不创建 Phase-18-06。
