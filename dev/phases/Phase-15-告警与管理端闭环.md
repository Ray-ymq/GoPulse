# Phase 15：告警与管理端闭环

> 本文档是阶段开发提纲。告警条件模型、状态机、查询契约和页面细节由总实施方案确定。

## 版本规划

- 版本线：`1.12.x`；阶段基线：`1.12.0`。
- 执行批次从 `1.12.1` 起编号，由 Phase 15 总实施方案统一分配版本与分支。

## 阶段目标

建立独立管理 Frontend、内部告警闭环和最终双角色模型。超级管理员进入管理端后默认看到可观测大屏、当前状态和告警记录。

## 身份与权限目标

- 角色只保留 `user` 与 `super_admin`。
- 用户端与管理端共用 Backend、用户数据库、登录体系和同源会话。
- 系统必须有一个不可删除、不可降级的引导超级管理员。
- 可存在多个超级管理员；任一超级管理员可按用户 ID 提升或降级非引导账号。
- Backend 执行最终授权；前端跳转和隐藏不构成权限控制。

## 开发范围

- 将既有管理员语义迁移为 `super_admin`，保持已完成数据与会话的可解释升级路径。
- 建立独立管理 Frontend 应用，不与用户 Frontend 共用业务页面和布局。
- 管理端首页为可观测大屏，汇总组件状态、关键 Metrics、Logs、Events、插件状态、当前告警和近期告警记录。
- 提供告警规则配置、启停、触发、持续、恢复和历史查询；输入来自既有 Metrics、Logs 与 Events。
- 告警只在管理后台内部呈现，不发送邮件、短信、Webhook 或其他外部通知。
- 提供按用户 ID 查询并调整角色的管理页面和审计事件。

## 最小端到端闭环

`超级管理员登录 → 进入独立管理端大屏 → 配置规则 → 真实异常触发告警 → 大屏和记录展示 → 数据恢复后告警恢复 → 操作留下审计事件`

## 验收标准

- 普通用户登录后只能进入用户端，直接访问管理页面或 API 不获得管理数据。
- 超级管理员登录后默认进入管理大屏，并可查看三类数据、六类插件和告警状态。
- 引导超级管理员不可删除或降级；其他账号可按用户 ID 在两种角色间调整，权限变更及时生效。
- 代表性 Metrics、Logs、Events 规则可触发并恢复，重复评估不会产生无界重复记录。
- 告警历史包含规则、严重程度、对象、首次/最近触发与恢复状态，但不泄漏 Secret 或原始凭据。
- 关闭告警评估或可观测依赖故障不会阻断用户端社交业务。

## 本阶段不做

- 外部通知渠道、值班排班、告警升级、自动修复或复杂关联分析。
- 多租户、细粒度 RBAC 或第三种角色。
- Kubernetes 告警对象或集群自动发现。

## 总实施方案约束

- 总方案必须定义最小告警状态机、重复抑制、恢复语义、角色迁移与引导账号保护。
- 页面批次必须使用真实 Backend 数据完成大屏和告警闭环，不接受静态演示数据。
- 角色负向矩阵和告警故障隔离属于固定完成门槛。
