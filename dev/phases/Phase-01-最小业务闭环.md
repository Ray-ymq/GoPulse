# Phase 1：最小业务闭环

> 本文档是阶段开发提纲，具体接口、数据模型、消息格式和部署参数将在本阶段进入详细设计时补充。

## 阶段目标

将 GoPulse 建设为具备用户、帖子、评论和点赞能力的最小可用社交平台。

本阶段完成后，应形成可独立运行和验证的结果，并能够直接支撑 Phase 2。

## 开发范围

- User、Post、Comment、Like 业务模块。
- MySQL 核心业务数据持久化。
- Redis 明确场景下的缓存。
- 登录、帖子、评论与点赞相关前端页面。

## 核心任务

- 在单体 Backend 内按业务边界组织模块。
- 完成用户创建及基础身份使用流程。
- 完成帖子发布、列表与详情能力。
- 完成评论和点赞流程。
- 建立必要缓存并保证缓存失效不影响事实数据。

## 前置依赖

- Phase 0 工程骨架完成。
- MySQL 与 Redis 可用。

## 阶段产物

- 最小业务 Backend。
- 最小社交业务前端。
- 核心业务数据持久化能力。
- 基础缓存能力。

## 验收标准

- 用户可完成创建用户、发布帖子、查询帖子、评论和点赞的完整流程。
- Backend 重启后核心数据仍存在。
- Redis 缓存失效不会导致业务数据丢失。
- MySQL 保持为业务事实来源。

## 本阶段不做

- RabbitMQ 业务异步化。
- Elasticsearch 全文搜索。
- 可观测系统。
- Kubernetes 部署。

## 后续待细化事项

- 具体代码目录与模块边界。
- 对外及内部接口定义。
- 数据结构、消息结构或存储结构。
- 配置项、运行参数与异常处理细节。
- 本阶段任务拆分、测试用例与实施顺序。
