# Phase 21：用户业务与管理服务分离

> 本页是阶段导航；版本、分支、范围、门禁与预算由[总实施方案](../imple/Phase-21/Phase-21-总实施方案.md)负责。
> 执行与能力状态查询[能力状态](../status/capability-status.md)及总方案引用的实际日志。

## 阶段结果

同一 Backend 制品提供业务与管理两种独立启动角色。业务服务处理登录和社交流程，管理服务处理观测查询、告警、插件及角色管理；保留同一账号库、数据库、Cookie 会话和现有 API 地址。旧 combined 模式支持迁移，最终 Compose 使用两个业务实例和一个管理实例。

Outbox 事件投递留在业务服务，告警评估由管理服务运行。本阶段不拆 dispatcher、不引入新业务或多目标采集，不进行容量认证或长时实验，也不依赖已取消的 Phase-20-05/06。

## 验收和能力边界

最终验证独立起停/就绪与路由、同账号会话和实时授权、用户发帖到搜索、真实管理查询/告警/插件、管理停止时已有会话业务继续、两个角色各自准入及实例采集、完整归属清理。

共享 MySQL 仍影响业务数据、认证和管理授权；同宿主及其他共享状态不构成完整故障隔离。短时定向验收不证明容量或长期稳定。实际交付、候选证据和未验证范围登记到[能力状态](../status/capability-status.md)与同名日志；本页不复制执行状态。
