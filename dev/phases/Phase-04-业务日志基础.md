# Phase 4：业务日志基础

> 本文档是阶段开发提纲，具体接口、数据模型、消息格式和部署参数将在本阶段进入详细设计时补充。

## 阶段目标

统一 Backend 业务日志，为后续 LogMonitor 与日志处理链路提供稳定数据源。

本阶段完成后，应形成可独立运行和验证的结果，并能够直接支撑 Phase 5。

## 开发范围

- Backend 结构化日志。
- 统一基础日志字段。
- 请求链路标识。
- 主要 API 的业务与错误日志。

## 核心任务

- 确定项目统一的结构化日志输出方式。
- 为主要 API 补齐关键过程日志。
- 在一次请求内传递 request_id。
- 确保日志可被后续采集组件稳定读取。

## 前置依赖

- Phase 3 业务搜索完成。
- Backend 主要业务接口已稳定。

## 阶段产物

- 统一格式的 Backend 业务日志。
- 可关联单次请求的日志链路。
- 供 LogMonitor 使用的真实日志源。

## 验收标准

- 主要 API 均输出统一格式日志。
- 日志至少可表达时间、级别、服务、模块、消息和 request_id。
- 可通过 request_id 关联一次请求中的关键日志。

## 本阶段不做

- LogMonitor。
- Kafka 日志传输。
- 日志写入 Elasticsearch。
- 完整日志查询平台。

## 后续待细化事项

- 具体代码目录与模块边界。
- 对外及内部接口定义。
- 数据结构、消息结构或存储结构。
- 配置项、运行参数与异常处理细节。
- 本阶段任务拆分、测试用例与实施顺序。
