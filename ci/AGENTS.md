# 测试与验收工具规则

本文件约束 `ci/` 下的治理、测试与验收工具；`dev/imple/AGENTS.md` 与
`dev/phases/AGENTS.md` 明确引用本文件，使规划也遵循工具复用与新增必要性要求。
[仓库规则](../AGENTS.md)保持最高优先级，已分配批次的范围、固定门禁、候选身份、
证据和执行预算仍由总实施方案及当前分方案决定。

## 1. 规划先核对已有验证能力

- 新增或修订规划时，先检索直接相关的测试、验收入口、公共夹具和实际调用；不能仅因
  新阶段开始就分配一套新的 runner、sampler、verifier 或环境管理程序。
- 实施分方案必须给出以下验证映射；阶段提纲说明复用方向，精确映射留在实施分方案。

| 字段 | 必须说明的内容 |
| --- | --- |
| 验证对象 | 本批改变的行为、缺陷或公共合同，以及成功和必要失败条件 |
| 已有覆盖 | 相关测试文件、用例或工具的实际路径；说明可直接复用的部分和具体缺口 |
| 最低有效层级 | 单元、集成、浏览器、真实系统、容量或制品/证据检查；选择理由 |
| 本批变更 | 复用入口、补用例/数据、扩展助手或新增执行器，以及精确允许修改的文件 |
| 固定门禁 | 实际命令、前置环境、期望结果、必要测量窗口和证据；待实现接口明确标记 |

执行成本计入原有分方案预算，遵循[实施耗时规则](../dev/rules/implementation-execution-budget.md)，
不另设一套时间上限。没有新增验证缺口时，明确复用已有检查，不为填满文件清单增加测试。

## 2. 按能力组织用例，复用执行基础设施

- Go 业务规则、HTTP/API、数据库事务、消息处理和后端链路优先放入所属模块的
  `_test.go`；真实依赖集成或后端端到端用例也可由 Go 测试承载。环境准备、隔离和清理
  仍须实际实现，不能以普通单元测试替代合同要求的真实依赖验收。
- 前端组件与状态行为优先使用现有 Vitest 用例；真实浏览器操作、同源代理、Cookie、
  焦点和可见结果使用 Playwright。相同业务在不同层验证不同边界时，可以同时保留。
- 新场景优先添加用例、fixture、profile 或数据文件；复用候选解析、HTTP/浏览器客户端、
  Compose 管理、资源归属、采样、失败传播、证据发布和清理助手。
- 不复制整套执行器再改阶段号或目标版本。用例和公共助手按能力命名；固定历史合同
  可以保留阶段身份，名称本身不构成退役理由。
- 薄 Shell/Make/Task 入口可以保留，用于提供稳定命令、参数和环境准备；行数少不是
  删除理由。兼容别名需有明确用途，避免把同一转发入口当成独立验证能力。
- 容量测量、独立采样、安装/恢复、制品身份和证据复核可保留专门程序。语言选择不能
  削弱真实测量窗口、外部故障控制、原始数据保留或候选绑定。

## 3. 新增执行器必须说明必要性

- 计划新增 runner、sampler 或 verifier 时，必须说明相关现有工具为何不能扩展或复用，
  新工具独有的执行方式或合同是什么，公共部分如何复用，以及后续维护和调用入口。
  “本阶段需要验收”或“已有文件属于旧阶段”不足以证明新工具必要。
- 业务断言与环境编排分开组织。共享助手放入明确的公共模块，避免新工具持续导入
  历史执行器获取公共函数；已有依赖的迁移须列入允许修改范围和受影响检查。
- 工具自测用于保护实际 CLI、失败传播、资源归属、持久数据/证据及统计合同，或复现
  已观察到的工具缺陷。不能仅检查源码字符串、文件存在或照抄实现步骤来冒充行为验证；
  对文件、schema 或静态边界本身的合同检查，应明确其验证对象。
- 不为减少文件数建设超出本批需求的通用框架，也不把工具开发隐藏在正式验收执行中。

## 4. 回归与退役必须保留有效覆盖

- 按本批实际变更选择直接检查和必要回归；不把每个历史阶段的完整矩阵自动加入新批次。
  明确各门禁的验证边界，避免在同一候选、相关输入和环境未变时重复执行同一检查。
- 若规划调整 CI，区分治理、产品测试、工具自测和专项验收，同一检查保持一个明确
  执行位置；不能为消除重复调用而丢掉原入口中独有的检查。
- 删除或归档测试/执行器前，核对代码导入、脚本调用、CI、有效实施方案和历史证据
  校验器；列出独有断言及其保留、迁移或随能力正式退役的依据。
- 执行器仍在使用、公共代码仍被导入或证据校验合同仍在维护时，保留对应必要自测。
  不仅凭旧阶段编号、暂未进入日常 CI 或存在 Go 测试就删除整份测试。
- 迁移或替换工具时，证明受影响的行为、失败退出、归属清理和证据合同仍成立；需要
  真实验收的边界不能只靠静态检查证明。更新有效调用和说明，保留历史日志及原始证据。

## 5. 已有合同的适用边界

这些规则用于后续新增或修订的工具及规划，不追溯改写已完成计划、日志、回执或验收结论。
若已有未执行方案需要改变工具接口、文件范围、固定门禁或批次分配，应先明确修订
对应权威方案；本文件本身不授权修改产品、删除测试、恢复暂停验收或重跑历史矩阵。
