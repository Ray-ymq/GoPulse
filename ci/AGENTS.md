# 测试与验收工具

适用于 ci 下的工具，以及新建或修订计划时的验证设计。分支、版本和证据遵循根
[AGENTS.md](../AGENTS.md)，固定门禁由当前实施方案定义。

## 先复用已有能力

| 验证对象 | 优先使用 |
| --- | --- |
| Go 行为、API、状态和消息 | 所属模块的 Go 测试；真实依赖使用既有 integration |
| 前端组件与状态 | Vitest；真实同源、Cookie、权限与交互使用 Playwright |
| 容器、插件、恢复和制品 | 现有 acceptance/lifecycle 的场景、fixture、profile 与公共助手 |
| 分支、版本和调度 | 现有治理工具及其行为测试 |

计划说明改变的行为、已有覆盖、具体缺口、最低有效层级、允许文件和固定命令。
命令尚未实现时明确标记，不把同名或静态检查当成真实门禁。

## 新增与验证

- 新执行器必须说明现有工具的具体缺口和独有合同；阶段号变化不构成理由。
  优先补用例或扩展助手，避免复制 runner、采样器和环境管理器。
- 业务断言和环境编排分开，公共函数不从历史执行器反向导入；薄 Make/CLI 入口可以保留。
- 自测证明实际参数、错误退出、资源归属、持久状态和证据合同，或复现观察到的缺陷。
  源码字符串断言只适用于静态合同，不能冒充运行行为验证。
- CI 与本地复用同一入口和必需参数。快检查不能替代合同要求的真实系统或测量窗口。

## 替换与退役

- 替换前查明独有断言、调用方和清理/证据行为；迁移后更新有效引用并运行受影响检查。
- 删除工具或测试须说明退役能力、决定和保留覆盖；仍被导入或仍保护有效合同的内容应保留。
- 历史日志、回执和原始证据保持原样；工具退役不能宣称相应产品能力已被替代。
