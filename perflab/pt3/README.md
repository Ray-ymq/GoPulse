# 测试三执行入口

本目录用于测试三的环境恢复、独立观测、故障停压和功能验证。测试三使用 [test3.json](../k6/test3.json)，不直接使用 `next.json`。

## 当前执行边界

测试三已于 2026-10-20 执行，结果见[性能测试报告](../../PT/03-测试三/2026-10-20-测试三-性能测试报告.md)。以下命令保留为复现入口。

```sh
# 从相同快照开始，连续执行 10、20、40、80、160、320、640、1280、2560 RPS。
python3 perflab/pt3/run.py

# 独立恢复后复测一个档位；每次调用都重新恢复快照。
python3 perflab/pt3/run.py --rps 160

# 最后正常档按 100% 请求率补测 30 分钟，另加 30 秒预热。
python3 perflab/pt3/run.py --rps 160 --measurement-seconds 1800
```

示例中的 160 RPS 是首次异常档，80 RPS 是最后正常档。边界二分按实际正常档和异常档选择中点；最终异常档独立调用三次。短时测量和持续测试均为 30 秒预热。每组结束后保留观测和少量真实读写探测 600 秒，不主动重启或清理积压。

`run.py` 在恢复环境前校验准备清单中的源码、配置、二进制和私有数据文件摘要。运行前必须存在 `.run/pt3/prepared.json`，且 `ready=true`。修改这些文件后必须重新验证并更新准备清单。不要使用旧二进制运行新脚本。

## 负载与统计

`continuous=true` 让 Go runner 使用同一个 k6 场景执行全部档位。脚本按场景时钟划分每档预热与测量窗口，跨档不重新登录，不重置请求序列，也不等待恢复。普通错误率、延迟和 `/ready` 退化只记录。

脚本保留现有业务比例：45% 读取、10% 搜索、10% 通知与书签等读取、15% 内容写入、15% 互动写入、5% 身份与会话。业务 VU 上限为 512，另有 1 个健康探测 VU；客户端超时为 5 秒。1024 VU 在 9 档连续场景下会在业务加压前触发压测器内存停压，见报告第 3.1 节。瞬时档位切换采用 0 秒 ramp，随后在该档保持 330 秒。

摘要包含每个窗口的实际秒数。提前停压时，runner 按停压时刻和场景开始时间修正窗口，排除 setup 和请求收尾时间；未执行档位不继承全局请求数。原始 dropped iterations 按时间归入相应档位和阶段。不能将未达到的目标 RPS 当作实际负载。

每秒请求记录按指标产生时间汇总，包含目标请求率、完成请求率、有效成功吞吐、错误率、总体与成功请求的 P95/P99、错误分类和丢弃迭代。档位判定使用完整正式窗口。删除 404 单独计数，归入非成功请求；只有 204 计入有效删除成功。连续组删除目标不循环，语料耗尽立即中止。

## 观测与停压

`observe.py` 复用仓库的 MySQL exporter 和官方 node_exporter，每 5 秒保存原始指标及已有应用指标。仅保留新连接 `SELECT 1`、数据库身份与数据版本及迁移校验、业务读写与异步恢复检查。它不直查数据库性能指标，不读取系统资源计数，不采集日志或剖析数据。当前准备及验证入口见[测试四工具](../pt4/README.md)。只复现测试三时，先运行 `python3 perflab/pt3/exporters.py` 准备专用 exporter，再按原流程验证准备清单。

连续 30 秒数据库探针失败且无成功才判定持续不可用。探针或环境样本过期、exporter 或应用指标采集失败会单独标记观测失败。数据库身份、数据 epoch、环境或迁移状态变化会停压。人工停止使用 `.run/pt3/STOP`，核对原因后再移除。

安全状态写入 `.run/pt3/guard.json`。runner 每 100 毫秒检查一次，要求停止或心跳超时后中断 k6，保留恢复观测。宿主可用内存低于 1 GiB、可用磁盘低于 20 GiB、主机 OOM、MySQL 已连接数达到 131 或未完成需求达到 9,000 时停压。资源指标来自 exporter；不再提供容器内存或 k6 RSS 的停压判断，也不使用主机指标替代容器指标。原报告保留当时的采集方式和阈值。

## 数据恢复与文件

私有配置、语料、账号、二进制、快照和原始记录均在 `.run/pt3/`，不提交凭据或业务明细。

`environment.py restore --name baseline` 停止测试服务，核对 SQL 快照摘要，清空本测试环境的队列，然后恢复数据库及搜索索引。该操作仅用于独立测试环境。搜索基线保留为只读克隆索引；恢复时克隆到新的物理索引并切换业务 alias，校验文档内容、版本和映射摘要后删除上一轮的业务物理索引。

克隆流程按 [Elasticsearch Clone API](https://www.elastic.co/docs/api/doc/elasticsearch/operation/operation-indices-clone) 设置源索引写入限制并等待目标分片就绪。MySQL SQL 快照和只读搜索基线用于本测试环境内恢复；搜索克隆与原索引使用同一 Elasticsearch 数据卷，不能替代异机灾备。

`seed.py` 只在改动前快照存在、正式基线快照尚未建立时补齐删除目标。`validate-corpus` 对全部账号验证密码，并检查目标存在性、归属、重复和删除目标与其他目标的重叠。

## 验证工具

以下测试使用离线样本或临时 HTTP 服务，不访问 GoPulse 业务接口：

```sh
node --check perflab/k6/workload.js
node --test perflab/k6/*.test.mjs
go -C perflab test -race -count=1 ./...
go -C perflab build -o ../.run/pt3/bin/load ./cmd/load
python3 -m unittest discover -s perflab/pt3 -p 'test_*.py'
```

模拟服务测试验证持续 503 不阻断下一档、观测状态触发中断、提前结束的实际时长以及丢弃迭代归档。数据库故障判据使用离线样本验证，不停止、重启或破坏真实数据库。
